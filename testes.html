Python Testes

A Ana escreveu uma função que calcula o preço com desconto. Para saber se ela funciona, rodou o programa, olhou o resultado e pensou "parece certo". Uma semana depois, mexeu na função para aceitar outra coisa e… será que o desconto antigo continua certo? Ela teria de conferir tudo de novo, de cabeça. Testes automáticos resolvem isso: pequenos programas que conferem os seus programas, sozinhos, em um segundo, quantas vezes você quiser.

Você vai aprender
  • O que é um teste: uma pergunta cuja resposta você já sabe.
  • A conferir com assert, e o que o AssertionError quer dizer.
  • A organizar testes com o módulo unittest: TestCase, assertEqual, assertRaises e companhia.
  • A rodar tudo com python3 -m unittest e a ler o relatório: os pontos, o F, o E.
  • A escrever exemplos nas docstrings que viram testes, com doctest.
  • Como é o pytest, a ferramenta de fora mais usada.
  • Os enganos comuns: arquivo com o nome errado, método sem test, sem self, centavos que não fecham.

A ideia: provar a receita antes de servir

Na padaria do bairro, a confeiteira não serve um bolo novo sem provar. E ela prova sempre do mesmo jeito: um pedaço, "está doce o bastante? a massa está fofa?". Ela sabe de antemão como o bolo certo tem de ser, e compara.

Um teste é isso: você chama a sua função com valores que você já sabe a resposta (100 reais com 10% de desconto têm de dar 90) e compara o que a função devolveu com o que devia devolver. Se bater, o teste passa. Se não bater, o teste falha e avisa onde.

1. A conferência mais simples: assert

Primeiro, o jeito "olhômetro": rodar e olhar.

def preco_com_desconto(preco, porcentagem):
    return preco - preco * porcentagem / 100

print(preco_com_desconto(100, 10))
print(preco_com_desconto(50, 20))

$ python3 desconto.py
90.0
40.0

Funciona, mas é você quem tem de olhar e decidir se 90.0 e 40.0 estão certos. O assert ("afirmar", "garantir") faz a comparação por você:

def preco_com_desconto(preco, porcentagem):
    return preco - preco * porcentagem / 100

assert preco_com_desconto(100, 10) == 90
assert preco_com_desconto(50, 20) == 40
assert preco_com_desconto(80, 0) == 80
print("Todos os testes passaram.")
assert
"Garanto que o que vem a seguir é verdade". Se for, o programa segue em silêncio. Se não for, ele para com um erro.
preco_com_desconto(100, 10) == 90
A condição: a função, chamada com 100 e 10, tem de devolver 90. O == compara (veja Comparações). 90.0 == 90 é True: um float e um int com o mesmo valor são iguais.
$ python3 com_assert.py
Todos os testes passaram.

Os três assert passaram calados, e o print do fim rodou. Agora, o que acontece se a função tiver um erro? A Ana, mexendo no código, esqueceu de multiplicar pelo preço:

def preco_com_desconto(preco, porcentagem):

assert preco_com_desconto(100, 10) == 90
print("Todos os testes passaram.")

O AssertionError sozinho não diz quanto a função devolveu. Dá para pôr uma mensagem depois de uma vírgula:

    return preco - porcentagem / 100

Agora a pista está na mensagem: veio 99.9, ou seja, a função tirou só 0,10 do preço (10 / 100), e não 10%.

O assert pode ser desligado

Quem roda o Python com a opção -O ("otimizar") faz todos os assert sumirem:

$ python3 assert_O.py
Traceback (most recent call last):
  File "/home/ana/assert_O.py", line 1, in <module>
    assert 1 == 2, "isso é falso"
           ^^^^^^
AssertionError: isso é falso
$ python3 -O assert_O.py
cheguei ao fim

Por isso, o assert serve para testes e para conferências do programador, nunca para validar o que o usuário digitou (para isso existem o if e o raise).

2. Organizando os testes: unittest

Com assert solto, o primeiro teste que falha para o programa, e você não fica sabendo dos outros. O módulo unittest ("teste de unidade": cada teste confere uma pequena parte, uma unidade) roda todos os testes, conta quantos passaram e mostra um relatório de cada falha.

O costume é separar em dois arquivos: o código de verdade e os testes dele. O código da lojinha:

"""Funções da lojinha da Ana."""


def preco_com_desconto(preco, porcentagem):
    """Devolve o preço depois de aplicar o desconto (em %)."""
    if not 0 <= porcentagem <= 100:
        raise ValueError("a porcentagem deve ficar entre 0 e 100")
    return preco - preco * porcentagem / 100


def total_do_carrinho(itens):
    """Soma preço × quantidade de cada item do carrinho."""
    return sum(preco * quantidade for preco, quantidade in itens)


def etiqueta(nome, preco):
    """Monta o texto da etiqueta de preço."""
    return f"{nome.upper()} - R$ {preco:.2f}".replace(".", ",")

E os testes, num arquivo cujo nome começa com test:

import unittest

from loja import etiqueta, preco_com_desconto, total_do_carrinho


class TestDesconto(unittest.TestCase):

    def test_dez_por_cento(self):
        self.assertEqual(preco_com_desconto(100, 10), 90)

    def test_sem_desconto(self):
        self.assertEqual(preco_com_desconto(80, 0), 80)

    def test_porcentagem_invalida(self):
        with self.assertRaises(ValueError):
            preco_com_desconto(100, 150)


class TestCarrinho(unittest.TestCase):

    def test_carrinho_vazio(self):
        self.assertEqual(total_do_carrinho([]), 0)

    def test_dois_itens(self):
        self.assertEqual(total_do_carrinho([(4.50, 2), (10.00, 1)]), 19.00)


class TestEtiqueta(unittest.TestCase):

    def test_etiqueta(self):
        self.assertEqual(etiqueta("café", 18.9), "CAFÉ - R$ 18,90")

    def test_comeca_com_o_nome(self):
        self.assertStartsWith(etiqueta("arroz", 27.9), "ARROZ")


if __name__ == "__main__":
    unittest.main()
from loja import …
Os testes importam as funções do loja.py, como qualquer módulo seu. Os dois arquivos ficam na mesma pasta.
class TestDesconto(unittest.TestCase):
Uma classe que herda de unittest.TestCase ("caso de teste"). Ela é só uma caixa para juntar testes do mesmo assunto. Você não precisa saber criar classes para usá-la: copie a forma.
def test_dez_por_cento(self):
Cada teste é um método cujo nome começa com test. É assim que o unittest o encontra. O self é obrigatório.
self.assertEqual(a, b)
"Confira que a é igual a b". Se não for, o teste falha e o relatório mostra os dois valores.
with self.assertRaises(ValueError):
"Confira que o código dentro do bloco lança um ValueError". Aqui, o teste passa quando dá erro: uma porcentagem de 150% tem de ser recusada.
self.assertStartsWith(texto, início) 3.14
"Confira que o texto começa com…". É novo no Python 3.14, junto com assertEndsWith; num Python mais antigo, use self.assertTrue(texto.startswith("ARROZ")).
unittest.main()
Roda os testes do arquivo quando você faz python3 test_loja.py. O if __name__ == "__main__": faz isso acontecer só quando o arquivo é rodado direto, e não quando é importado.

F ou E: onde procurar

Um F diz "a resposta veio errada": olhe o valor que veio, e descubra quem errou a conta (o código ou o valor esperado no teste). Um E diz "o teste quebrou no meio": leia o traceback como qualquer outro erro do Python (veja Lendo uma Mensagem de Erro).

As conferências mais usadas

MétodoPassa quando…
assertEqual(a, b) / assertNotEqual(a, b)a == b / a != b
assertTrue(x) / assertFalse(x)x é verdadeiro / falso
assertIs(a, b) / assertIsNone(x)a is b / x is None
assertIn(a, b) / assertNotIn(a, b)a in b / a not in b
assertIsInstance(x, tipo)x é do tipo dado
assertAlmostEqual(a, b)a e b são iguais até a 7ª casa decimal (para float)
assertGreater(a, b) / assertLess(a, b)a > b / a < b
with assertRaises(Erro):O bloco lança aquele erro
assertStartsWith(t, s) / assertEndsWith(t, s) 3.14O texto t começa / termina com s
assertHasAttr(obj, nome) 3.14O objeto tem o atributo com esse nome

Por que não usar assert dentro do TestCase? Funciona, mas os métodos assert… dão mensagens melhores: o assertEqual mostra os dois valores (14.5 != 19.0), o assertIn mostra o item e a lista.

3. Testes nos exemplos da docstring: doctest

Lembra das docstrings, os textos de explicação no começo das funções? Muita gente põe nelas um exemplo de uso, copiado do modo interativo (>>>). O módulo doctest transforma esses exemplos em testes: ele roda cada linha com >>> e confere se a resposta é exatamente a que está escrita embaixo.

def preco_com_desconto(preco, porcentagem):
    """Devolve o preço depois de aplicar o desconto (em %).

    >>> preco_com_desconto(100, 10)
    90.0
    >>> preco_com_desconto(50, 20)
    40.0
    >>> preco_com_desconto(100, 150)
    Traceback (most recent call last):
        ...
    ValueError: a porcentagem deve ficar entre 0 e 100
    """
    if not 0 <= porcentagem <= 100:
        raise ValueError("a porcentagem deve ficar entre 0 e 100")
    return preco - preco * porcentagem / 100


def parcelas(total, vezes):
    """Divide o total em parcelas iguais, arredondadas em centavos.

    >>> parcelas(100, 4)
    [25.0, 25.0, 25.0, 25.0]
    >>> parcelas(10, 3)
    [3.33, 3.33, 3.33]
    """
    return [round(total / vezes, 2)] * vezes


if __name__ == "__main__":
    import doctest
    doctest.testmod()

4. Uma espiada no pytest

O pytest não vem com o Python, mas é a ferramenta de testes mais usada nos projetos de hoje. Nele, um teste é uma função comum com nome começando por test_, e a conferência é um assert simples, sem classe e sem self.assertEqual:

from loja import preco_com_desconto, total_do_carrinho


def test_dez_por_cento():
    assert preco_com_desconto(100, 10) == 90


def test_dois_itens():
    assert total_do_carrinho([(4.50, 2), (10.00, 1)]) == 19.00


def test_desconto_grande():
    assert preco_com_desconto(200, 25) == 140

import unittest


def formatar_telefone(numeros):
    """'86999990001' vira '(86) 99999-0001'."""
    numeros = numeros.strip()
    if len(numeros) != 11 or not numeros.isdigit():
        raise ValueError(f"telefone inválido: {numeros!r}")
    return f"({numeros[:2]}) {numeros[2:7]}-{numeros[7:]}"


class TestTelefone(unittest.TestCase):

    def test_formata(self):
        self.assertEqual(formatar_telefone("86999990001"), "(86) 99999-0001")

    def test_com_espacos(self):
        self.assertEqual(formatar_telefone(" 86999990002 "), "(86) 99999-0002")

    def test_curto_demais(self):
        with self.assertRaises(ValueError):
            formatar_telefone("8699999")

    def test_com_letras(self):
        with self.assertRaises(ValueError):
            formatar_telefone("86abc990001")


unittest.main()

Resumo

  • Um teste chama o seu código com valores de resposta conhecida e compara. Passou, silêncio (ou um ponto); falhou, um relatório.
  • assert condição, "mensagem" é a conferência mais simples; para no primeiro erro e some com python3 -O.
  • unittest: classes que herdam de unittest.TestCase, métodos test…(self), conferências self.assertEqual, assertRaises, assertAlmostEqual…
  • python3 -m unittest acha os arquivos test*.py e roda tudo. No relatório: . passou, F resposta errada, E exceção no meio. Confira o Ran N tests.
  • doctest testa os exemplos >>> das docstrings, comparando o texto. Silêncio quer dizer que passou.
  • pytest (instalado num venv) usa funções e assert simples, com um relatório detalhado.
