Python Herança

A Ana está montando o cadastro do petshop da vizinha. Todo animal tem nome e come; o cachorro, além disso, busca a bolinha; o gato mia em vez de latir. Escrever três classes do zero, repetindo o nome e o comer em todas, seria trabalho dobrado, e cada correção teria de ser feita três vezes. A herança resolve: você escreve uma classe geral, Animal, e cria classes filhas, Cachorro e Gato, que recebem tudo o que a mãe tem e só acrescentam ou mudam o que é diferente.

Você vai aprender
  • A criar uma classe filha com class Cachorro(Animal):, e o que ela herda.
  • A acrescentar métodos na filha e a sobrescrever (trocar) um método da mãe.
  • A usar super() para aproveitar o __init__ e os métodos da mãe.
  • A perguntar "é um?" com isinstance e "é filha de?" com issubclass.
  • Como o Python procura um método: primeiro na filha, depois na mãe (__mro__).
  • Quando usar herança ("é um") e quando guardar um objeto dentro do outro ("tem um").
  • Os erros reais: o super().__init__ esquecido, o self a mais, a mãe criada depois da filha e o método com nome errado.

A ideia: "é um"

Na ficha do petshop há uma parte que vale para todo animal (nome, idade, vacinas) e uma parte que muda: o cachorro tem raça e porte; o peixe, o tipo de aquário. A herança segue a mesma lógica da frase "é um": um cachorro é um animal, um gato é um animal. Tudo o que vale para animal vale também para cachorro.

O rex sabe comer (herdou da mãe) e buscar (escrito na filha). Repare que o buscar usa o self.nome, criado pelo __init__ da mãe: tudo se mistura num objeto só. Mas a herança vai num sentido só: da mãe para a filha. Um Animal qualquer não ganhou o buscar, e daí o AttributeError. Nem todo animal busca bolinha.

3. Sobrescrevendo: a filha faz do seu jeito

Se a filha escreve um método com o mesmo nome de um método da mãe, o da filha vale para ela. Isso se chama sobrescrever (em inglês, override, "passar por cima").

class Animal:
    def __init__(self, nome):
        self.nome = nome

    def falar(self):
        print(f"{self.nome} faz um som.")


class Cachorro(Animal):
    def falar(self):
        print(f"{self.nome} diz: Au au!")


class Gato(Animal):
    def falar(self):
        print(f"{self.nome} diz: Miau!")


class Peixe(Animal):
    pass


for bicho in [Cachorro("Rex"), Gato("Mimi"), Peixe("Nemo")]:
    bicho.falar()

$ python3 sobrescrever.py
Rex diz: Au au!
Mimi diz: Miau!
Nemo faz um som.                   « o Peixe não sobrescreveu: usou o da mãe

Como o Python decide qual falar usar? Ele procura o método primeiro na classe do objeto; se não achar, sobe para a mãe. No Cachorro, achou logo. No Peixe, não achou e subiu para o Animal. É a mesma busca da aula Atributos e Métodos (primeiro o objeto, depois a classe), com mais um andar: depois da classe, a mãe.

4. super(): aproveitando o __init__ da mãe

O cachorro precisa guardar a raça, além do nome. Então ele precisa do seu próprio __init__. Mas o __init__ da filha sobrescreve o da mãe, e aí ninguém guardaria o nome. A solução é a filha chamar o __init__ da mãe, para ela fazer a parte dela, e depois fazer a sua:

class Animal:
    def __init__(self, nome):
        self.nome = nome

    def falar(self):
        print(f"{self.nome} faz um som.")


class Cachorro(Animal):
    def __init__(self, nome, raca):
        super().__init__(nome)
        self.raca = raca

    def falar(self):
        print(f"{self.nome}, o {self.raca}, diz: Au au!")


rex = Cachorro("Rex", "vira-lata")
print(rex.nome, rex.raca)
rex.falar()
print(vars(rex))
def __init__(self, nome, raca):
O __init__ do cachorro recebe tudo o que um cachorro precisa: o nome (que todo animal tem) e a raça (só dele).
super()
"A classe de cima", a mãe. super() dá acesso aos métodos da mãe, mesmo os que a filha sobrescreveu.
super().__init__(nome)
Chama o __init__ do Animal, que guarda o self.nome. Sem self nos parênteses: o super() já sabe qual é o objeto.
self.raca = raca
Depois, a parte que só o cachorro tem.
$ python3 super_init.py
Rex vira-lata
Rex, o vira-lata, diz: Au au!
{'nome': 'Rex', 'raca': 'vira-lata'}

O vars(rex) mostra os dois atributos num objeto só: o nome, guardado pelo __init__ da mãe, e a raca, pelo da filha. O costume é chamar o super().__init__ na primeira linha do __init__ da filha: primeiro a parte geral, depois a específica.

super() em outros métodos

O super() serve para qualquer método, não só o __init__. Use quando a filha quer fazer o mesmo que a mãe e mais um pouco. Uma conta poupança mostra o saldo como qualquer conta, mais uma linha sobre o rendimento:

class ContaBancaria:
    def __init__(self, titular, saldo=0):
        self.titular = titular
        self.saldo = saldo

    def mostrar(self):
        print(f"{self.titular}: R$ {self.saldo:.2f}")


class ContaPoupanca(ContaBancaria):
    def __init__(self, titular, saldo=0, taxa=0.01):
        super().__init__(titular, saldo)
        self.taxa = taxa

    def render(self):
        self.saldo += self.saldo * self.taxa

    def mostrar(self):
        super().mostrar()
        print(f"  (poupança, rende {self.taxa:.0%} ao mês)")


corrente = ContaBancaria("Ana", 500)
poupanca = ContaPoupanca("Bia", 1000)
poupanca.render()

corrente.mostrar()
poupanca.mostrar()

$ python3 conta.py
Ana: R$ 500.00
Bia: R$ 1010.00
  (poupança, rende 1% ao mês)

O mostrar da poupança chama o super().mostrar() (a linha com o titular e o saldo, escrita uma vez só, na mãe) e acrescenta a sua linha. Se um dia o banco mudar o jeito de mostrar o saldo, a mudança na mãe vale para as duas contas. (O :.0% mostra o 0.01 como porcentagem sem casas: 1%. Veja a Formatação.)

5. "É um?": isinstance e issubclass

    pass

    pass

    pass

$ python3 isinst.py

True                               « …e também é um Animal
False                              « mas não é um Gato
False                              « o type() só olha a classe exata

True: um cachorro é um animal. O isinstance aceita a classe do objeto e todas as mães dela. Era isso que a aula Classes e Objetos prometeu: por isso ele é preferido ao type() ==, que responde False aqui.
issubclass(Cachorro, Animal)
Pergunta sobre as classes, não sobre objetos: "Cachorro é filha (ou neta…) de Animal?".
Cachorro.__mro__
A ordem de busca dos métodos (MRO, de method resolution order, "ordem de resolução de métodos"): primeiro Cachorro, depois Animal, por fim object, a mãe de todas as classes.
Herança múltipla: uma palavra

Em Python, uma classe pode ter mais de uma mãe: class Pato(Voador, Nadador):. O pato recebe os métodos das duas.

class Voador:
    def voar(self):
        print("Voando!")


class Nadador:
    def nadar(self):
        print("Nadando!")


class Pato(Voador, Nadador):
    pass


donald = Pato()
donald.voar()
donald.nadar()
print(Pato.__mro__)

$ python3 multipla.py
Voando!
Nadando!
(<class '__main__.Pato'>, <class '__main__.Voador'>, <class '__main__.Nadador'>, <class 'object'>)

O __mro__ diz a ordem da busca: se as duas mães tiverem um método com o mesmo nome, vale o da que aparece primeiro. A herança múltipla tem regras próprias e é fácil de embaralhar; para quem está começando, uma mãe só basta para quase tudo.

Formas diferentes: herdar ou guardar dentro?

Herança não é o único jeito de aproveitar uma classe. Outro, muito comum, é um objeto guardar outro como atributo. Isso se chama composição, e segue a frase "tem um": a aluna tem um endereço (ela não é um endereço).

class Endereco:
    def __init__(self, rua, cidade):
        self.rua = rua
        self.cidade = cidade


class Aluno:
    def __init__(self, nome, endereco):
        self.nome = nome
        self.endereco = endereco


casa = Endereco("Rua das Flores, 10", "Teresina")
bia = Aluno("Bia", casa)
print(bia.nome, "mora em", bia.endereco.cidade)

$ python3 composicao.py
Bia mora em Teresina

O bia.endereco.cidade se lê da esquerda para a direita: o endereco da bia (um objeto Endereco), e a cidade dele.

Uma armadilha clássica: fazer class Aluno(Endereco): só para "ganhar" a rua e a cidade. Funciona, mas a frase fica errada ("um aluno é um endereço?"), e o aluno herda coisas de endereço que não fazem sentido para ele.

Quando dá errado

Esquecer o super().__init__

        self.nome = nome

  File "/home/ana/sem_super.py", line 13, in <module>

AttributeError: 'Cachorro' object has no attribute 'nome'

O cachorro nasceu sem nome. O __init__ da filha sobrescreveu o da mãe, e o Python não chama o da mãe sozinho: quem não chamou, ficou sem. O nome até chegou como parâmetro, mas ninguém o guardou. Como consertar: comece o __init__ da filha com super().__init__(nome).

Lendo de baixo para cima: o erro foi na linha 8, dentro do __init__ do cachorro, que tinha sido chamado pela linha 12. "O Animal.__init__() recebe 2 argumentos (self e nome), mas ganhou 3". O super() já passa o objeto como self, sozinho, como o rex.falar() passa o rex. O self escrito à mão foi o terceiro. Como consertar: super().__init__(nome).

Resumo

  • class Filha(Mae): cria uma classe que herda tudo da mãe: __init__, métodos, atributos de classe. Use quando a frase "a filha é uma mãe" fizer sentido.
  • A filha pode acrescentar métodos (só ela ganha) e sobrescrever métodos da mãe, com o mesmo nome exato.
  • O Python procura um método primeiro na classe do objeto, depois na mãe, até object: é o __mro__.
  • Se a filha tem __init__, ela precisa chamar super().__init__(…), sem self, para a mãe fazer a parte dela.
  • super().metodo() aproveita o método da mãe para "fazer o mesmo e mais um pouco".
  • isinstance(obj, Mae) é True também para objetos das filhas; issubclass(Filha, Mae) pergunta sobre as classes.
  • "Tem um" é composição (self.endereco = …), não herança. Herança múltipla existe, mas uma mãe basta para quase tudo.
