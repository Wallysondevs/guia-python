Python Dicas de Tipo (Type Hints)

Olhe esta linha: def total(preco, quantidade):. O preço é um número com casas decimais ou um texto como "R$ 2,50"? A quantidade pode ser 1.5? E a função devolve o quê? No Python, nada disso precisa ser dito: qualquer variável aceita qualquer tipo. Mas você pode dizer, escrevendo dicas de tipo (em inglês, type hints): def total(preco: float, quantidade: int) -> float:. Elas deixam o código mais fácil de entender, ajudam o editor de código a sugerir e avisar, e ferramentas próprias conseguem achar erros antes de você rodar o programa. Só tem um detalhe importante, e é o centro desta aula: o Python, sozinho, não confere essas dicas.

Você vai aprender
  • A anotar o tipo dos parâmetros (n: int), do valor devolvido (-> int) e das variáveis.
  • Que as dicas são só dicas: o programa roda mesmo com o tipo errado (e você vai ver o que acontece).
  • A escrever tipos de coleções: list[float], dict[str, float], tuple[str, int].
  • A dizer "pode ser este tipo ou nada" com | None.
  • Como uma ferramenta como o mypy usa as dicas para achar erros.
  • As anotações "preguiçosas" do Python 3.14 3.14 e o __annotations__.

A ideia: a etiqueta da tomada

Ao lado de algumas tomadas da casa da Ana há uma etiqueta: 220V. A etiqueta não impede ninguém de ligar ali um secador de 127V; ela só avisa. Quem lê a etiqueta antes não queima o secador.

As dicas de tipo são essas etiquetas. quantidade: int avisa "aqui vai um número inteiro". O Python não impede você de passar um texto, do mesmo jeito que a etiqueta não trava a tomada. Mas quem lê o código, o editor de código e as ferramentas de checagem leem a etiqueta e avisam antes do estrago.

1. Anotando uma função

def dobro(n: int) -> int:
    return n * 2


print(dobro(5))
n: int
Depois do nome do parâmetro, dois-pontos e o tipo esperado: "n deve ser um int" (número inteiro; aula Tipos de Dados).
-> int
Uma setinha (hífen e sinal de maior) antes dos dois-pontos do def: o tipo do valor que a função devolve com o return (aula return). Lê-se "devolve um int".
:
O dois-pontos do fim do def continua lá, depois da setinha.
O resto
O corpo da função é igual ao de sempre. As dicas não mudam o que a função faz.

Com vários parâmetros, cada um ganha a sua dica:

def total(preco: float, quantidade: int) -> float:
    return preco * quantidade

Uma função que não devolve nada (só mostra algo na tela, por exemplo) leva -> None (aula O Valor None):

def avisar(mensagem: str) -> None:
    print("Atenção:", mensagem)

2. O Python não confere as dicas

Agora o teste. A função diz que espera um int. O que acontece se você passar um texto, ou uma lista?

def dobro(n: int) -> int:
    return n * 2


print(dobro(5))
print(dobro("ab"))
print(dobro([1, 2]))

$ python3 dobro.py
10
abab
[1, 2, 1, 2]

Rodou, sem nenhuma reclamação. O Python ignorou a dica e fez o que * 2 faz com cada tipo: com número, multiplica; com texto, repete ("ab" * 2 é "abab", aula Juntar e Repetir Textos); com lista, também repete. A função "funcionou", mas devolveu um texto e uma lista, quando a etiqueta prometia um int.

Às vezes, o tipo errado não passa calado: ele explode lá dentro da função, longe de onde o erro de verdade aconteceu.

def total(preco: float, quantidade: int) -> float:
    return preco * quantidade


print(total(2.5, 3))
print(total(2.5, "3"))

Missão: a quantidade chegou do input(), como texto, e o programa dá TypeError. A dica quantidade: int diz o que a função espera: converta a quantidade com int() antes de chamar a função (aula Conversão de Tipos).

def total(preco: float, quantidade: int) -> float:
    return preco * quantidade


quantidade = "3"  # veio do input(), é texto
print(total(2.5, quantidade))

def total(preco: float, quantidade: int) -> float:
    return preco * quantidade


quantidade = "3"  # veio do input(), é texto
print(total(2.5, int(quantidade)))

3. Dicas em variáveis e em coleções

Variáveis também podem ter dica: o nome, dois-pontos, o tipo, e depois o = de sempre. E para listas e dicionários, você diz o tipo dos itens entre colchetes:

def media(notas: list[float]) -> float:
    return sum(notas) / len(notas)


turma: list[float] = [7.5, 8.0, 6.5]
resultado: float = media(turma)
print(resultado)
print(media.__annotations__)

4. "Pode não ter": | None

A Ana tem uma tabela de preços e uma função que procura um produto nela. Se o produto existe, a função devolve o preço; se não existe, devolve None. Como dizer isso na dica? Com a barra vertical |, que aqui quer dizer "ou":

def buscar_preco(produto: str, tabela: dict[str, float]) -> float | None:
    if produto in tabela:
        return tabela[produto]
    return None


precos = {"pão": 0.75, "leite": 5.5}
print(buscar_preco("leite", precos))
print(buscar_preco("café", precos))

$ python3 busca.py
5.5
None
-> float | None
"Devolve um float ou None." Quem chama a função fica avisado: o resultado pode não ser um número, e é preciso tratar esse caso (com um if preco is None:, aula is e in).
dict[str, float]
A tabela: nomes de produtos (texto) ligados a preços (float).

O uso mais comum do | None é num parâmetro com valor padrão None (aula Valores Padrão):

def saudacao(nome: str | None = None) -> str:
    if nome is None:
        return "Olá, visitante!"
    return f"Olá, {nome}!"


print(saudacao("Ana"))
print(saudacao())

$ python3 saudacao.py
Olá, Ana!
Olá, visitante!

A ordem é: o nome, a dica (str | None) e depois o valor padrão (= None). O mesmo | serve para outros tipos: int | float quer dizer "inteiro ou com casas decimais".

O Optional dos códigos mais antigos

Em código escrito para versões antigas do Python, você vai encontrar Optional[str] (do módulo typing) no lugar de str | None, e List[int], com L maiúsculo, no lugar de list[int]. Querem dizer a mesma coisa. Nas versões atuais (o 3.14 do guia, o 3.13 do Debian), prefira as formas curtas, str | None e list[int], que não precisam de import.

5. Quem confere as dicas: o mypy

Se o Python não confere, para que escrever? Porque outros programas conferem. O mais conhecido é o mypy: ele lê o seu arquivo, sem rodá-lo, e compara cada chamada com as dicas. O mypy não vem com o Python; ele é instalado com o pip, dentro de um ambiente virtual (as aulas pip e venv mostram como). Os editores de código, como o VS Code, fazem uma checagem parecida enquanto você digita e sublinham os erros em vermelho.

Vale a pena para quem está começando?

Em programas pequenos, como os das aulas, as dicas são opcionais. Elas começam a valer muito quando o programa cresce e é dividido em vários arquivos, ou quando outras pessoas vão usar as suas funções: a dica responde na hora "o que eu passo aqui?", sem ninguém precisar ler o corpo da função. Junto com a docstring, é a melhor etiqueta que uma função pode ter.

6. As anotações preguiçosas do Python 3.14 3.14

No Python 3.14, as dicas passaram a ser avaliadas de um jeito "preguiçoso" (é a mudança descrita nas PEPs 649 e 749). Até o 3.13, o Python calculava as dicas no momento em que lia o def. Agora, ele guarda as dicas sem calculá-las, e só as calcula quando alguém pede, por exemplo ao ler o __annotations__.

Na prática, isso deixa você usar numa dica um nome que só vai existir mais adiante no arquivo. Aqui, a função usa o tipo Produto, que é uma classe (aula Classes e Objetos) criada só depois:

def cadastrar(produto: Produto) -> None:
    print("Cadastrado:", produto.nome)


class Produto:
    def __init__(self, nome: str):
        self.nome = nome


cadastrar(Produto("café"))
print(cadastrar.__annotations__)

$ python3 adiantado.py
Cadastrado: café
{'produto': <class '__main__.Produto'>, 'return': None}

Quando o Python leu o def cadastrar, o nome Produto ainda não existia, e não houve erro. Na última linha, quando o __annotations__ foi pedido, a classe já existia, e a dica foi calculada sem problema.

Se você tem o Python 3.13 (o do Debian 13) ou mais antigo

Nessas versões, as dicas são calculadas na hora do def. Pela documentação oficial (What's New in Python 3.14), o adiantado.py acima pararia logo na linha 1 com um NameError, porque Produto ainda não existe. (Não rodamos isso: o laboratório do guia tem o 3.14.) O jeito antigo de contornar é escrever a dica entre aspas, produto: "Produto", o que funciona em todas as versões. No 3.14, as aspas deixaram de ser necessárias.

Formas diferentes de fazer a mesma coisa

def total(preco, quantidade):
    return preco * quantidade

def total(preco, quantidade):
    """Devolve o preço (float, em reais) vezes a quantidade (int)."""
    return preco * quantidade

def total(preco: float, quantidade: int) -> float:
    """Devolve o valor total da compra, em reais."""
    return preco * quantidade
FormaQuando usar
Sem dicasProgramas pequenos e rápidos, como os exercícios das aulas. É Python válido e muito comum

Dicas de tipo + docstringFunções que outras pessoas (ou você, daqui a meses) vão usar, e programas maiores. As dicas dizem os tipos; a docstring diz o resto

Quando dá errado

A seta errada: => no lugar de ->

Quem conhece JavaScript costuma escrever a seta com um sinal de igual:

def dobro(n: int) => int:
    return n * 2

$ python3 seta.py
  File "/home/ana/seta.py", line 1
    def dobro(n: int) => int:
                      ^
SyntaxError: expected ':'

"Esperava :." Depois dos parênteses do def, o Python só aceita a seta -> (hífen e maior) ou os dois-pontos. O ^ aponta para o =. Não há Traceback: o programa nem começou a rodar. Como consertar: def dobro(n: int) -> int:.

Achar que a dica converte o valor

A dica quantidade: int não transforma o "3" em 3. Você viu na seção 2: o texto chegou como texto até a conta, e lá veio o TypeError: can't multiply sequence by non-int of type 'float'. Com dobro("ab") foi pior: nenhum erro, e um resultado errado (abab). Como consertar: converta você mesmo, com int() e float(), o que vem do input() ou de arquivos; e use o mypy ou o editor de código para conferir as dicas.

Resumo

  • Dicas de tipo dizem que tipo cada coisa deve ter: n: int no parâmetro, -> int no retorno, idade: int = 30 na variável.
  • O Python não confere as dicas. Com o tipo errado, o programa roda (e às vezes dá um resultado errado ou um TypeError lá dentro).
  • Coleções: list[float], dict[str, float], tuple[str, int]. "Ou": float | None, str | None = None.
  • Quem confere é uma ferramenta como o mypy (ou o seu editor de código), que lê o arquivo sem rodá-lo.
  • As dicas ficam em funcao.__annotations__.
  • 3.14 As dicas agora são calculadas só quando alguém pede: dá para usar um nome definido mais adiante, sem aspas. No 3.13, escreva esse nome entre aspas.
