Python pathlib

Nas aulas anteriores, a Ana abriu, leu e gravou arquivos com open(). Mas os arquivos de verdade não ficam soltos: ficam dentro de pastas, que ficam dentro de outras pastas. A lojinha da Ana já tem uma pasta loja, com a lista de produtos, a lista de clientes e uma pasta só para as vendas de cada mês. Para o programa saber onde cada arquivo está, criar pastas novas, conferir se um arquivo existe antes de abrir e listar o que há dentro de uma pasta, o Python tem o módulo pathlib (de path, "caminho", e lib, de library, "biblioteca").

Você vai aprender
  • O que é um caminho e como criar um com Path.
  • A juntar pedaços de caminho com a barra /, sem se preocupar com o sistema.
  • A pegar as partes de um caminho: name, stem, suffix, parent.
  • A perguntar se um arquivo ou pasta existe: exists(), is_file(), is_dir().
  • A criar pastas com mkdir(), e as opções parents e exist_ok.
  • A ler e gravar um arquivo inteiro numa linha: read_text() e write_text().
  • A listar uma pasta com iterdir() e procurar arquivos com glob() e rglob().
  • Os erros reais: FileNotFoundError, FileExistsError, IsADirectoryError, a barra entre dois textos e a pasta que não está vazia.

A ideia: o endereço de um arquivo

Para mandar uma carta para a Ana, você escreve o endereço do mais geral para o mais específico: cidade, bairro, rua, número. O computador faz igual com os arquivos. O arquivo janeiro.txt da lojinha mora assim:

/home/ana/loja/vendas/janeiro.txt

Lendo da esquerda para a direita: começando da raiz do disco (a primeira /), entre na pasta home, depois na pasta ana, depois em loja, depois em vendas, e lá dentro está o arquivo janeiro.txt. Esse "endereço" se chama caminho (em inglês, path). Cada / separa uma pasta da próxima.

Tipo de caminhoExemploQuer dizer
Absoluto (completo)/home/ana/loja/produtos.txtO endereço inteiro, a partir da raiz do disco. Começa com /
Relativoloja/produtos.txt"A partir de onde eu estou agora": a pasta loja que está na pasta atual

Quando você roda python3 programa.py no terminal da Ana, a "pasta atual" é a pasta em que o terminal está (no começo, /home/ana). No editor do guia, é a pasta do programa. Nos exemplos desta aula, quase todos os caminhos são relativos: funcionam igual nos dois lugares.

1. O primeiro Path

Dentro do módulo pathlib mora o Path ("caminho"). Você o traz para o seu programa com from pathlib import Path (a aula Módulos e import explica essa linha em detalhe) e cria um caminho passando o texto dele:

from pathlib import Path

arquivo = Path("compras.txt")
print(arquivo)
print(type(arquivo))
from pathlib import Path
"Do módulo pathlib, traga o Path." Sem essa linha, o Python não conhece o nome Path.
Path("compras.txt")
Cria um objeto caminho a partir do texto "compras.txt". Ele ainda não abre nem cria nada: é só o endereço, anotado num papel.
arquivo = …
Guarda o caminho na variável arquivo, como qualquer outro valor.
print(arquivo)
Mostra o caminho como texto.
$ python3 caminho.py
compras.txt
<class 'pathlib.PosixPath'>

O print mostrou o caminho sem aspas, e o type revelou que ele não é um texto (str), e sim um PosixPath: um caminho no estilo do Linux e do macOS (POSIX é o nome do padrão que esses sistemas seguem). No Windows, o mesmo programa mostraria WindowsPath. Você não precisa escolher: escreva sempre Path, e o Python usa o tipo certo para o sistema.

O caminho não precisa existir

Repare que não existe nenhum compras.txt na pasta da Ana, e mesmo assim o programa funcionou. Criar um Path é como anotar um endereço: anotar não constrói a casa. O erro só aparece quando você tenta usar o arquivo (ler, por exemplo), como você vai ver em Quando dá errado.

2. Juntando pedaços com a barra /

O jeito mais bonito do pathlib é a barra. Entre um Path e um texto, o / não é divisão: é "entre nesta pasta". Assim você monta um caminho pedaço por pedaço:

from pathlib import Path

pasta = Path("loja")
arquivo = pasta / "vendas" / "janeiro.txt"

print(arquivo)
print("Nome:", arquivo.name)
print("Sem a extensão:", arquivo.stem)
print("Extensão:", arquivo.suffix)
print("Pasta onde está:", arquivo.parent)
print("Partes:", arquivo.parts)

$ python3 partes.py
loja/vendas/janeiro.txt
Nome: janeiro.txt
Sem a extensão: janeiro
Extensão: .txt
Pasta onde está: loja/vendas
Partes: ('loja', 'vendas', 'janeiro.txt')
pasta / "vendas"
Um Path barra um texto dá um Path novo: loja/vendas. Dá para encadear quantas barras quiser.
.name
O nome do último pedaço, com a extensão: janeiro.txt.
.stem
O nome sem a extensão (stem = "talo", a parte principal): janeiro.
.suffix
A extensão, com o ponto (suffix = "sufixo"): .txt.
.parent
A pasta "mãe", onde o arquivo está (parent = "pai/mãe"): loja/vendas. Também é um Path.
.parts
Todos os pedaços, numa tupla.

Repare: name, stem, suffix e parent não levam parênteses. Eles não fazem nada no disco; só leem pedaços do próprio endereço. São atributos, informações que o objeto já tem.

Por que não escrever "loja/vendas/janeiro.txt" de uma vez?

Funciona no Linux, mas o Windows separa as pastas com a barra invertida (loja\vendas\janeiro.txt). Com Path("loja") / "vendas" / "janeiro.txt", o Python escreve o separador certo para cada sistema, e o seu programa roda nos dois sem mudar uma letra.

Missão: a Ana guardou as vendas de março no arquivo marco.txt, dentro da pasta 2026, que fica dentro de vendas, que fica dentro de loja. Monte esse caminho com barras / a partir de Path("loja") e rode: o programa deve mostrar o caminho e a extensão.

from pathlib import Path

arquivo = Path("loja")

print(arquivo)
print("Extensão:", arquivo.suffix)

from pathlib import Path

arquivo = Path("loja") / "vendas" / "2026" / "marco.txt"

print(arquivo)
print("Extensão:", arquivo.suffix)

Três perguntas que o Path responde sobre o computador:

from pathlib import Path

print("Pasta atual:", Path.cwd())
print("Pasta pessoal:", Path.home())

arquivo = Path("compras.txt")
print("Caminho completo:", arquivo.absolute())

EscritaO que responde

4. Existe? É arquivo? É pasta?

Antes de abrir um arquivo, dá para perguntar se ele está lá. As respostas são booleanos (True ou False):

from pathlib import Path

for nome in ["Documentos", "compras.txt", "existe.py"]:
    caminho = Path(nome)
    print(nome)
    print("  existe?", caminho.exists())
    print("  é arquivo?", caminho.is_file())
    print("  é pasta?", caminho.is_dir())

$ python3 existe.py
Documentos
  existe? True
  é arquivo? False
  é pasta? True
compras.txt
  existe? False
  é arquivo? False
  é pasta? False
existe.py
  existe? True
  é arquivo? True
  é pasta? False
.exists()
"Existe?" Verdadeiro se houver qualquer coisa com esse nome: arquivo ou pasta.
.is_file()
"É um arquivo?" Falso para pastas e para o que não existe.
.is_dir()
"É uma pasta?" (dir vem de directory, "diretório", outro nome para pasta.)

Esses levam parênteses: são métodos, ações que vão até o disco olhar. A pasta Documentos existe e é pasta; compras.txt não existe, então as três respostas são False; e o próprio programa existe.py é um arquivo.

O uso mais comum é num if, para não tentar ler o que não está lá:

from pathlib import Path

arquivo = Path("loja") / "produtos.txt"
if arquivo.exists():
    print(arquivo.read_text(encoding="utf-8"))
else:
    print("Ainda não existe a lista de produtos.")

5. Criando pastas: mkdir()

mkdir vem de make directory, "criar pasta" (o mesmo nome do comando do terminal). A Ana vai criar a pasta da loja e, dentro dela, vendas/2026:

from pathlib import Path

loja = Path("loja")
loja.mkdir()
print("Criei a pasta", loja)

vendas = loja / "vendas" / "2026"
vendas.mkdir(parents=True)
print("Criei a pasta", vendas)

loja.mkdir(exist_ok=True)
print("A pasta loja já existia, e tudo bem")

$ python3 pastas.py
Criei a pasta loja
Criei a pasta loja/vendas/2026
A pasta loja já existia, e tudo bem
$ tree loja                             « o comando tree desenha as pastas
loja
└── vendas
    └── 2026

3 directories, 0 files
loja.mkdir()
Cria uma pasta. A pasta de cima tem de existir (aqui é a pasta atual, que existe).
mkdir(parents=True)
Cria também as pastas do meio que faltarem (parents = "os pais"). Sem isso, criar loja/vendas/2026 daria erro, porque vendas ainda não existia.
mkdir(exist_ok=True)
"Tudo bem se já existir" (exist ok). Sem isso, criar uma pasta que já existe dá erro.

O tree ("árvore") é um programa do terminal que desenha as pastas uma dentro da outra; a última linha (em inglês) conta 3 pastas e nenhum arquivo. E se a Ana rodar o programa de novo? A primeira linha, loja.mkdir(), sem exist_ok, tenta criar uma pasta que agora existe:

$ python3 pastas.py
Traceback (most recent call last):
  File "/home/ana/pastas.py", line 4, in <module>
    loja.mkdir()
    ~~~~~~~~~~^^
  File "/usr/lib/python3.14/pathlib/__init__.py", line 1012, in mkdir
    os.mkdir(self, mode)
    ~~~~~~~~^^^^^^^^^^^^
FileExistsError: [Errno 17] File exists: 'loja'

Leia o traceback de baixo para cima. A última linha é o que aconteceu: FileExistsError, "erro: o arquivo existe", File exists: 'loja'. Para o sistema, uma pasta também é um tipo de "arquivo", por isso a mensagem fala em file. Acima dela há dois trechos de código: o primeiro é a linha 4 do programa da Ana (loja.mkdir()); o segundo é de dentro do próprio pathlib, onde o erro de fato estourou. Quando o traceback passa por arquivos do Python (os que começam com /usr/lib/python3.14/), procure a última linha que é sua: é ela que você conserta.

A receita que não falha, e que você vai ver em muitos programas, é juntar as duas opções:

from pathlib import Path

Path("loja", "vendas", "2026").mkdir(parents=True, exist_ok=True)
print("Pronto, e sem erro")

$ python3 receita.py
Pronto, e sem erro
$ python3 receita.py                    « de novo: nada de FileExistsError
Pronto, e sem erro

Cria o que faltar e não reclama do que já existe. (Repare em mais um jeito de montar o caminho: Path("loja", "vendas", "2026"), com os pedaços separados por vírgula, é o mesmo que Path("loja") / "vendas" / "2026".)

6. Ler e gravar sem open(): read_text() e write_text()

Para arquivos de texto pequenos, o Path tem dois atalhos que fazem o open, o with, o read/write e o fechamento numa linha só:

from pathlib import Path

arquivo = Path("loja") / "produtos.txt"
arquivo.write_text("café\naçúcar\npão de queijo\n", encoding="utf-8")
print("Gravei", arquivo)

texto = arquivo.read_text(encoding="utf-8")
print(texto)
print("O arquivo tem", len(texto.splitlines()), "linhas")

$ python3 escrever.py

$ cat loja/produtos.txt                 « o cat do terminal mostra o arquivo gravado

arquivo.write_text(texto, encoding="utf-8")
"Escreva este texto": cria o arquivo (ou apaga o conteúdo antigo e escreve por cima, como o modo "w" do open), grava e fecha.
arquivo.read_text(encoding="utf-8")
"Leia o texto": abre, lê tudo num str só e fecha.
encoding="utf-8"
A codificação, que diz como os acentos viram bytes. Sempre escreva, como você aprendeu em Abrindo Arquivos: assim o "café" chega inteiro em qualquer computador.

A linha em branco depois de "pão de queijo" é o \n do fim do arquivo somado ao \n do próprio print. O splitlines() quebra o texto nas linhas e o len conta: 3.

Para o programa descobrir o que tem dentro de uma pasta, use iterdir() (de iterate directory, "percorrer a pasta"). Ele entrega um Path para cada coisa que está diretamente dentro da pasta:

from pathlib import Path

loja = Path("loja")
for item in sorted(loja.iterdir()):
    if item.is_dir():
        print("[pasta]  ", item.name)
    else:
        print("[arquivo]", item.name)

$ python3 listar.py
[arquivo] clientes.txt
[arquivo] produtos.txt
[pasta]   vendas
loja.iterdir()
Os itens que estão dentro de loja, um por vez, cada um como um Path (loja/clientes.txt, loja/vendas…). Não entra nas subpastas: o que está dentro de vendas não aparece.
sorted(…)
Coloca em ordem alfabética (aula Ordenando Listas).
item.is_dir()
Separa as pastas dos arquivos.
item.name
Só o nome, sem o loja/ na frente.
Sem sorted, a ordem é a do disco

O iterdir() entrega os itens na ordem em que o sistema guardou, que não é alfabética e pode mudar de um computador para outro. Se a ordem importa (quase sempre importa, para quem lê), passe por sorted().

8. Procurando arquivos: glob() e rglob()

E se a Ana quiser só os arquivos .txt? O glob procura pelos nomes que combinam com um molde, onde o * quer dizer "qualquer coisa" (é o mesmo curinga do terminal: ls *.txt).

from pathlib import Path

loja = Path("loja")

print("Os .txt da pasta loja:")
for arquivo in sorted(loja.glob("*.txt")):
    print(" ", arquivo)

print("Os .txt em qualquer lugar dentro de loja:")
for arquivo in sorted(loja.rglob("*.txt")):
    print(" ", arquivo)

$ python3 procurar.py

  loja/clientes.txt
  loja/produtos.txt
Os .txt em qualquer lugar dentro de loja:
  loja/clientes.txt
  loja/produtos.txt
  loja/vendas/2026/marco.txt
  loja/vendas/fevereiro.txt
  loja/vendas/janeiro.txt
MoldeEncontra

loja.glob("*")Tudo o que está direto em loja (parecido com iterdir())
loja.glob("vendas/*.csv")Os .csv dentro de loja/vendas
loja.glob("*a*")Os nomes que têm a letra a em qualquer lugar
loja.glob("vendas/janeiro.???")? é exatamente um caractere qualquer: janeiro.txt, janeiro.csv…

O notas.csv não apareceu em nenhuma das duas buscas: o molde pedia .txt. E o rglob desceu até vendas/2026/marco.txt, que o glob não enxerga. Como no iterdir, use sorted() para ter uma ordem garantida.

9. Apagando: unlink() e rmdir()

from pathlib import Path

rascunho = Path("loja") / "rascunho.txt"
rascunho.write_text("teste\n", encoding="utf-8")
print("Existe?", rascunho.exists())

rascunho.unlink()
print("Depois do unlink, existe?", rascunho.exists())

rascunho.unlink(missing_ok=True)
print("Apagar de novo, com missing_ok=True, não deu erro")

vazia = Path("loja") / "vazia"
vazia.mkdir()
vazia.rmdir()
print("A pasta vazia foi apagada:", not vazia.exists())

$ python3 apagar.py
Existe? True
Depois do unlink, existe? False
Apagar de novo, com missing_ok=True, não deu erro
A pasta vazia foi apagada: True
.unlink()
Apaga um arquivo (unlink = "desligar", o nome técnico de apagar no Linux). Se o arquivo não existir, dá FileNotFoundError.
.unlink(missing_ok=True)
"Tudo bem se estiver faltando": não reclama se o arquivo já não existe.
.rmdir()
Apaga uma pasta vazia (remove directory). Com qualquer coisa dentro, ela se recusa.
Apagar é para sempre

O unlink() não manda o arquivo para a lixeira: ele some de vez, sem pergunta. Antes de rodar um programa que apaga arquivos, confira o caminho com um print. Que o rmdir() só apague pastas vazias é uma proteção a seu favor.

Formas diferentes de montar um caminho

Antes do pathlib (que existe desde o Python 3.4), os caminhos eram textos comuns, montados com a função os.path.join. Você ainda vai encontrar muito código assim:

import os.path
from pathlib import Path

jeito_antigo = os.path.join("loja", "vendas", "janeiro.txt")
jeito_novo = Path("loja") / "vendas" / "janeiro.txt"

print(jeito_antigo, type(jeito_antigo))
print(jeito_novo, type(jeito_novo))
print(str(jeito_novo) == jeito_antigo)

$ python3 ospath.py
loja/vendas/janeiro.txt <class 'str'>
loja/vendas/janeiro.txt <class 'pathlib.PosixPath'>
True

O mesmo endereço, só que um é texto e o outro é um Path. O str(caminho) transforma o Path em texto quando alguma função antiga exigir.

FormaQuando usar
Path("loja") / "vendas" / "janeiro.txt"O jeito moderno e o do guia. Fácil de ler, funciona em qualquer sistema e já dá acesso a name, exists(), read_text()…
Path("loja", "vendas", "janeiro.txt")O mesmo caminho; prático quando os pedaços já estão separados
Path("loja/vendas/janeiro.txt")Funciona; o Path entende a / no texto, até no Windows. Bom para caminhos fixos e curtos
os.path.join("loja", "vendas", "janeiro.txt")Código antigo. Funciona, mas devolve um texto e não tem os métodos do Path
"loja" + "/" + "janeiro.txt"Evite: é fácil esquecer ou dobrar a barra, e no Windows o separador é outro
Python mais antigo

No Python 3.13 (o do Debian 13), o type() de um caminho aparece como <class 'pathlib._local.PosixPath'>, com um _local no meio. É só o lugar onde a classe mora por dentro; o uso é idêntico.

Quando dá errado

Ler um arquivo que não existe: FileNotFoundError 
from pathlib import Path

arquivo = Path("loja") / "precos.txt"
texto = arquivo.read_text(encoding="utf-8")
print(texto)

$ python3 ler_falta.py
Traceback (most recent call last):
  File "/home/ana/ler_falta.py", line 4, in <module>
    texto = arquivo.read_text(encoding="utf-8")
  File "/usr/lib/python3.14/pathlib/__init__.py", line 788, in read_text
    with self.open(mode='r', encoding=encoding, errors=errors, newline=newline) as f:
         ~~~~~~~~~^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  File "/usr/lib/python3.14/pathlib/__init__.py", line 772, in open
    return io.open(self, mode, buffering, encoding, errors, newline)
           ~~~~~~~^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
FileNotFoundError: [Errno 2] No such file or directory: 'loja/precos.txt'

Um traceback comprido, mas só a primeira e a última parte interessam:

  • File "/home/ana/ler_falta.py", line 4: o problema começou na linha 4 do seu programa, o read_text.
  • As duas partes do meio (/usr/lib/python3.14/pathlib/…) são o caminho que o erro fez dentro do pathlib: o read_text chamou o open, que chamou o io.open. Não é ali que você conserta.
  • FileNotFoundError: [Errno 2] No such file or directory: 'loja/precos.txt': "arquivo não encontrado: não existe esse arquivo ou pasta". O [Errno 2] é o número que o sistema dá para esse erro.

Como consertar: confira o nome (era produtos.txt?) e a pasta atual; ou pergunte antes com if arquivo.exists():; ou trate o erro com try/except FileNotFoundError (aula try e except).

Barra entre dois textos: TypeError 
caminho = "loja" / "produtos.txt"
print(caminho)

$ python3 barra_texto.py
Traceback (most recent call last):
  File "/home/ana/barra_texto.py", line 1, in <module>
    caminho = "loja" / "produtos.txt"
              ~~~~~~~^~~~~~~~~~~~~~~~
TypeError: unsupported operand type(s) for /: 'str' and 'str'

"Tipos de operando não suportados para /: str e str." O ^ embaixo aponta para a barra. A barra só vira "entrar na pasta" quando pelo menos um dos lados é um Path; entre dois textos, ela é a divisão, e texto não se divide. Como consertar: comece com um Path: Path("loja") / "produtos.txt".

Texto no lugar de Path: AttributeError 
arquivo = "loja/produtos.txt"
print(arquivo.exists())

$ python3 texto_exists.py
Traceback (most recent call last):
  File "/home/ana/texto_exists.py", line 2, in <module>
    print(arquivo.exists())
          ^^^^^^^^^^^^^^
AttributeError: 'str' object has no attribute 'exists'

Repare nos parênteses em (loja / "fotos").mkdir(…): primeiro a barra monta o caminho, depois o mkdir age sobre ele. Sem os parênteses, o Python tentaria fazer "fotos".mkdir(), e texto não tem mkdir.

Resumo

  • Um caminho é o endereço de um arquivo ou pasta. from pathlib import Path e Path("loja") criam um, sem mexer no disco.
  • A barra / entre um Path e um texto junta pedaços: Path("loja") / "vendas" / "janeiro.txt", com o separador certo em qualquer sistema. Entre dois textos, ela dá TypeError.
  • name, stem, suffix, parent leem pedaços do endereço (sem parênteses).
  • exists(), is_file(), is_dir() perguntam ao disco.
  • mkdir(parents=True, exist_ok=True) cria a pasta e as do meio, sem reclamar se já existir.
  • read_text() e write_text() leem e gravam o arquivo inteiro numa linha; sempre com encoding="utf-8".
  • iterdir() lista a pasta; glob("*.txt") procura direto nela; rglob desce às subpastas. Use sorted() para ter ordem.
  • unlink() apaga um arquivo para sempre; rmdir() só apaga pasta vazia.
  • No traceback, procure a última linha que é do seu programa; as de /usr/lib/python3.14/ são de dentro do Python.
