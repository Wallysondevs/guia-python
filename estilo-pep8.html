Python PEP 8

Os dois programas abaixo fazem exatamente a mesma coisa e mostram o mesmo resultado. Um deles você entende em segundos; o outro, você precisa decifrar. A diferença não está no que o código faz, está no jeito de escrever. A comunidade Python combinou um jeito, escrito num documento chamado PEP 8, e quase todo código Python que você vai encontrar segue esse combinado. Nesta aula você aprende as regras principais e as ferramentas que conferem (e até arrumam) o código por você.

Você vai aprender
  • O que é a PEP 8 e por que estilo importa, se o Python roda de qualquer jeito.
  • Indentação, tamanho da linha e linhas em branco.
  • Como dar nome a variáveis, funções, classes, constantes e módulos.
  • Onde vão (e onde não vão) os espaços.
  • Como organizar os imports, e por que evitar from modulo import *.
  • Comparações no estilo do Python: is None, if lista:, sem == True.
  • As ferramentas ruff e black, com a saída real.
  • Os erros de verdade que um nome mal escolhido causa.

A ideia: letra legível e ortografia combinada

Um bilhete escrito às pressas, sem pontuação, com abreviações que só você entende, até passa a mensagem. Mas quem lê sofre. Por isso existem a ortografia e as regras de pontuação: todo mundo escreve do mesmo jeito, e todo mundo lê sem esforço.

Com código é igual. O Python aceita muita coisa, mas um programa é lido muito mais vezes do que é escrito: por você mesma daqui a um mês, por quem vai continuar o seu trabalho, por quem vai ajudar a achar um erro. A PEP 8 é a "ortografia" do Python.

TermoO que é
PEPPython Enhancement Proposal, "proposta de melhoria do Python": os documentos numerados em que a linguagem é discutida e decidida. Toda novidade do Python nasce de uma PEP (veja as Novidades)

1. Indentação: 4 espaços

No Python, a indentação (o recuo no começo da linha) não é enfeite: é ela que diz o que está dentro do for, do if, da função (veja Sintaxe e Indentação). O Python aceita qualquer quantidade de espaços, desde que você seja coerente dentro do bloco. O baguncado.py usa 2 espaços num lugar, 6 em outro e 4 na classe, e funciona. A PEP 8 combina: 4 espaços por nível, sempre.

def calcular_total(itens):
    total = 0  # 1 nível: 4 espaços
    for preco, quantidade in itens:
        total += preco * quantidade  # 2 níveis: 8 espaços
    return total

E a tecla Tab? A PEP 8 prefere espaços. Os editores de código (VS Code, o editor deste guia e outros) já trocam o Tab por 4 espaços sozinhos. O que não pode é misturar os dois no mesmo bloco: o Python recusa (veja Quando dá errado).

2. Nomes

Cada tipo de coisa tem o seu jeito de escrever o nome. Assim, só de olhar, você sabe se Carrinho é uma classe e se calcular_total é uma função.

Mais quatro conselhos sobre nomes:

  • Diga o que é. for preco, quantidade in itens: se lê sozinho; for i in Itens: com i[0] e i[1] obriga quem lê a adivinhar. Letras soltas (i, x) só para contadores e contas curtas.
  • Nunca use l (L minúsculo), O (o maiúsculo) ou I (i maiúsculo) sozinhos como nome. Em muitas fontes eles se confundem com 1 e 0: l = 1, O = 0.
  • Não use nomes que o Python já usa, como list, str, sum, id, input: você esconde a função embutida (o erro está em Quando dá errado). Se o nome bom é uma palavra reservada, a PEP 8 sugere um sublinhado no fim: class_, id_.
  • Sem acento, por costume. O Python 3 aceita preço = 10, mas quase ninguém escreve assim (é difícil de digitar em teclados de outros países). Este guia usa preco.

4. Linhas: tamanho e linhas em branco

No máximo 79 caracteres

A PEP 8 pede linhas de até 79 caracteres (72 nos comentários e docstrings), para caber em janelas estreitas e em dois arquivos lado a lado. Muitas equipes combinam um limite um pouco maior (o black e o ruff usam 88; a própria PEP 8 aceita até 99 quando a equipe concorda). Para quebrar uma linha comprida, use os parênteses: dentro de ( ), [ ] ou { }, o Python deixa você continuar na linha de baixo.

# comprida demais (111 caracteres)
mensagem = f"Olá, {nome_do_cliente}! O seu pedido de número {numero_do_pedido} saiu para entrega e chega hoje."

# quebrada com parênteses: dois textos seguidos viram um só
mensagem = (
    f"Olá, {nome_do_cliente}! O seu pedido de número {numero_do_pedido} "
    "saiu para entrega e chega hoje."
)

# uma chamada com muitos argumentos: um por linha
total = calcular_total(
    itens=carrinho,
    cliente_fiel=True,
    cupom="PADARIA10",
)

A vírgula depois do último argumento (cupom="PADARIA10",) é permitida e costumeira quando cada item está na sua linha: acrescentar um item depois mexe numa linha só. Existe também a barra invertida \ no fim da linha para continuar na próxima, mas a PEP 8 prefere os parênteses.

Linhas em branco

  • Duas linhas em branco antes e depois de cada função e classe "de fora" (as que não estão dentro de outra coisa).
  • Uma linha em branco entre os métodos dentro de uma classe.
  • Dentro de uma função, uma linha em branco de vez em quando para separar as "etapas", como parágrafos de um texto. Sem exagero.

Volte ao arrumado.py e repare: duas linhas antes de def calcular_total, duas antes de class Carrinho, duas antes do print final.

5. imports

import csv
import json
from pathlib import Path

import requests

from loja import calcular_total
  1. No começo do arquivo (depois só da docstring do módulo, se houver).
  2. Um módulo por linha: import csv e import json, e não import csv, json. (Já from pathlib import Path, PurePath, vários nomes do mesmo módulo, pode.)
  3. Em três grupos, separados por uma linha em branco: primeiro a biblioteca padrão (o que vem com o Python: csv, json, pathlib); depois os pacotes instalados com o pip (como o requests); por último os seus módulos (loja). Dentro de cada grupo, em ordem alfabética, por costume.
  4. Evite from modulo import * ("importe tudo"): ninguém sabe de onde veio cada nome, e um nome importado pode esconder outro, como o open do exemplo em Quando dá errado.
  5. Não importe o que não usa. O baguncado.py importava sys e os sem usar nenhum dos dois.

8. As ferramentas: ruff e black

Ninguém confere a PEP 8 de olho. Há programas que fazem isso: os linters (de lint, os fiapos de tecido que grudam na roupa) apontam os problemas, e os formatadores reescrevem o código no estilo certo. Os dois mais usados hoje são o ruff (linter e formatador) e o black (formatador). Eles não vêm com o Python: a Ana instalou os dois num ambiente virtual.

"Uma coerência tola…"

A própria PEP 8 tem uma seção com o título "Uma coerência tola é o duende das mentes pequenas". Ela diz: o mais importante é a coerência dentro de um projeto, e uma regra pode ser quebrada quando segui-la deixaria o código menos legível. As regras servem à legibilidade, e não o contrário.

Quando dá errado

Estilo ruim, na maior parte das vezes, não quebra nada: só dificulta a leitura. Mas algumas escolhas de estilo provocam erros de verdade.

Tab e espaços misturados

No arquivo abaixo, a linha 2 começa com 4 espaços e a linha 3, com um Tab. No editor de texto as duas parecem alinhadas:

def saudacao(nome):
    mensagem = "Olá, " + nome
	return mensagem

print(saudacao("Ana"))

$ python3 tab.py
  File "/home/ana/tab.py", line 3
    	return mensagem
    ^
TabError: inconsistent use of tabs and spaces in indentation

"Uso inconsistente de tabs e espaços na indentação." O Python não tem como saber quantos espaços "vale" um Tab, então recusa a mistura. Repare que o erro aparece antes de o programa rodar (não há Traceback): é um erro de sintaxe. Como consertar: troque o Tab por 4 espaços. Configure o seu editor para inserir espaços quando você aperta Tab (quase todos já vêm assim).

"Um objeto list não pode ser chamado." Na linha 1, o nome list passou a ser a lista de compras, e não mais a função que cria listas. Como consertar: dê um nome que diga o que é: compras = [...]. O mesmo vale para str, sum, max, input, id, type.

Resumo

  • A PEP 8 é o guia de estilo do Python: o jeito combinado de escrever, porque o código é lido muito mais vezes do que é escrito.
  • 4 espaços de indentação (nunca misturados com Tab); linhas de até 79 caracteres, quebradas com parênteses; 2 linhas em branco entre funções e classes, 1 entre métodos.
  • Nomes: minusculas_com_sublinhado para variáveis e funções, PalavrasComMaiuscula para classes, MAIUSCULAS para constantes. Nada de l/O/I sozinhos, nem de nomes embutidos como list.
  • Espaços em volta de = e operadores e depois da vírgula; nenhum dentro dos parênteses, nem no = de argumento nomeado. Uma instrução por linha.
  • Imports no topo, um por linha, em grupos; sem import *. Compare com is None; teste a verdade com if x:.
  • ruff check aponta os problemas; ruff format e black arrumam o estilo. Bons nomes continuam sendo com você.
