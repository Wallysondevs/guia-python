Python type()

Na aula Tipos de Dados você viu que todo valor tem um tipo, e que o tipo muda tudo: 15 + 27 dá 42, mas "15" + "27" dá "1527". Só que, olhando para uma variável, nem sempre dá para saber o tipo do que está guardado nela. A função type() (em inglês, "tipo") responde a essa pergunta. Ela é a lupa do programador: quando um resultado sai estranho, perguntar o tipo é muitas vezes o primeiro passo para achar o erro.

Você vai aprender
  • A perguntar o tipo de um valor, de uma variável e do resultado de uma conta com type().
  • A ler a resposta: o que quer dizer <class 'int'>.
  • A usar type() para descobrir por que um programa deu 1527 em vez de 42.
  • A conferir se um valor é de um tipo: type(x) == int, e a armadilha de comparar com "int".
  • A conhecer o isinstance(), o jeito mais usado de conferir tipos.
  • Os erros reais: type() vazio, Type com maiúscula e o nome do tipo entre aspas.

Os programas desta aula foram rodados com o Python 3.14 na máquina fictícia da Ana (usuária ana, computador notebook), com python3 arquivo.py.

A ideia: ler o rótulo da embalagem

Na despensa da padaria, dois potes iguais, sem nada escrito: um tem sal, o outro tem açúcar. Por fora, não dá para saber. Antes de pôr a colher no bolo, a Ana vira o pote e lê o rótulo no fundo.

Uma variável é como esse pote: vendas pode guardar o número 15 ou o texto "15", e o print mostra os dois do mesmo jeito, 15. O type() vira o pote e lê o rótulo: diz se ali dentro tem um int, um str, um float…

O type() devolve o tipo, mas não mostra nada sozinho num programa. Quem mostra é o print, como sempre.

A resposta. class ("classe") é o nome que o Python dá a um tipo; entre as aspas vem o nome do tipo, aqui int. Os sinais < e > só marcam que aquilo é uma descrição, e não um texto comum. Leia como "é do tipo int".

2. O tipo de variáveis e de contas

Dentro dos parênteses pode ir qualquer coisa que tenha valor: uma variável, uma conta, o que uma função devolveu. O type() responde o tipo do valor que está ali naquele momento:

preco = 7.5
quantidade = 3
total = preco * quantidade
print(type(preco))
print(type(quantidade))
print(type(total))
print(type(7 / 2), type(10 // 2), type(3 + 0.5))

$ python3 ty-var.py
<class 'float'>
<class 'int'>
<class 'float'>
<class 'float'> <class 'int'> <class 'float'>
  • type(preco): o Python troca o nome pelo valor, 7.5, e responde float.
  • type(total): 7.5 * 3 dá 22.5; um float vezes um int dá float.
  • type(7 / 2): a divisão com / sempre dá float. Já o //, a divisão inteira (aula Operadores Aritméticos), deu int.

Só o nome do tipo

Para mostrar o tipo numa frase, sem o <class '…'> em volta, peça só o nome com .__name__ (dois sublinhados de cada lado; em inglês, "nome"):

estoque = 12
print("estoque é do tipo", type(estoque).__name__)

$ python3 ty-nome.py
estoque é do tipo int

Esse ponto depois do type(estoque) quer dizer "pegue uma informação de dentro dele". Você vai ver muitos pontos assim a partir da aula Métodos de Texto; por enquanto, basta saber que type(x).__name__ dá o nome do tipo como texto.

4. Conferindo se um valor é de um tipo

Às vezes você não quer só ver o tipo, quer perguntar: "isto é um inteiro?". O nome do tipo, sem aspas, pode ser comparado com o == ("é igual?"), e a resposta é um bool, True ou False:

idade = 29
print(type(idade) == int)
print(type(idade) == str)
print(type(idade) == "int")

$ python3 ty-compara.py
True
False
False
type(idade) == int
"O tipo de idade é int?" Sim: True. Aqui int vai sem aspas: é o próprio tipo, o mesmo nome que você usa em int(input(...)).
type(idade) == str
"É str?" Não: False.
type(idade) == "int"
Cuidado: deu False, sem erro nenhum. Com aspas, "int" é um texto de três letras, e o tipo int não é igual a um texto. A pergunta está errada e a resposta engana.

Essas respostas True/False vão ficar úteis quando o programa começar a tomar decisões, com o if ("se"), na aula if.

O isinstance()

Existe uma segunda função para essa pergunta, e é a que os programadores Python mais usam: isinstance(), de is instance, "é uma instância de", ou seja, "é um exemplar de". Ela recebe dois valores: o que você quer testar e o tipo.

idade = 29
preco = 7.5
print(isinstance(idade, int))
print(isinstance(preco, int))
print(isinstance(preco, (int, float)))
print(isinstance(preco, int | float))
print(isinstance("29", int))

$ python3 ty-isinstance.py
True
False
True
True
False
isinstance(idade, int)
"idade é um int?" Sim.
isinstance(preco, int)
7.5 é float, não int: False.
isinstance(preco, (int, float))
Vários tipos entre parênteses, separados por vírgula: "é int ou float?". Sim. É o jeito de perguntar "é um número?".
isinstance(preco, int | float)
A mesma pergunta, escrita com a barra vertical |, que aqui se lê "ou". Funciona desde o Python 3.10.
isinstance("29", int)
Com aspas, "29" é texto: False.
Por que existem dois jeitos?

O type(x) == int pergunta "o tipo é exatamente int?". O isinstance(x, int) pergunta "é um int, ou um tipo que é uma variação de int?". A diferença aparece num caso curioso: para o Python, o bool é uma variação do int (True vale 1 nas contas). Então type(True) == int dá False, mas isinstance(True, int) dá True. Essa história de "tipos que são variações de outros" se chama herança e fica para a aula Herança. Por enquanto, a regra prática: para conferir um tipo, prefira isinstance(); use type() para ver qual é o tipo.

Missão: o programa pergunta se preco é um int, e a resposta é False. Mude a pergunta para "é int ou float?", com o isinstance(), para a resposta ser True.

preco = 7.5
print(isinstance(preco, int))

preco = 7.5
print(isinstance(preco, (int, float)))

Quando dá errado

type() sem nada, ou com dois valores 
print(type())

$ python3 ty-err-vazio.py
Traceback (most recent call last):
  File "/home/ana/ty-err-vazio.py", line 1, in <module>
    print(type())
          ~~~~^^
TypeError: type() takes 1 or 3 arguments

"type() recebe 1 ou 3 argumentos". Com zero não dá. Com dois valores, como type(12, 7.5), a mensagem é a mesma. O jeito com 3 argumentos serve para criar tipos novos, coisa avançada que você não vai precisar; para perguntar o tipo, é sempre um valor. Como consertar: um type() para cada valor: print(type(12), type(7.5)).

Type com maiúscula 
print(Type(29))

$ python3 ty-err-Type.py
Traceback (most recent call last):
  File "/home/ana/ty-err-Type.py", line 1, in <module>
    print(Type(29))
          ^^^^
NameError: name 'Type' is not defined. Did you mean: 'type'?

Como com o Print da aula print(): o Python diferencia maiúsculas, e a dica "Did you mean" já diz o conserto: type, minúsculo.

O nome do tipo entre aspas no isinstance() 
print(isinstance(29, "int"))

$ python3 ty-err-texto.py
Traceback (most recent call last):
  File "/home/ana/ty-err-texto.py", line 1, in <module>
    print(isinstance(29, "int"))
          ~~~~~~~~~~^^^^^^^^^^^
TypeError: isinstance() arg 2 must be a type, a tuple of types, or a union

"O argumento 2 do isinstance() tem de ser um tipo, uma tupla de tipos ou uma união". O segundo valor foi o texto "int", e não o tipo int. (A "tupla de tipos" é o (int, float); a "união" é o int | float.) Aqui, pelo menos, o Python avisa; com type(x) == "int", ele só responde False em silêncio (seção 4). Como consertar: sem aspas, isinstance(29, int).

Nome do tipo por extenso 
print(isinstance(29, integer))

$ python3 ty-err-nome.py
Traceback (most recent call last):
  File "/home/ana/ty-err-nome.py", line 1, in <module>
    print(isinstance(29, integer))
                         ^^^^^^^
NameError: name 'integer' is not defined

O tipo se chama int, abreviado, e não integer. O mesmo vale para str (e não string) e bool (e não boolean). Como consertar: use os nomes curtos, exatamente como o type() mostra: int, float, str, bool.

Uma variável chamada type

Na aula Nomes de Variáveis você viu que dá para criar uma variável com o nome de uma função do Python, e que isso esconde a função. Com type é igual: depois de type = "pão doce", qualquer type(…) do programa dá TypeError: 'str' object is not callable. Use outro nome, como tipo ou categoria.

Resumo

  • type(valor) devolve o tipo de um valor, de uma variável ou do resultado de uma conta; num programa, mostre com print.
  • A resposta <class 'int'> se lê "é do tipo int". Para só o nome, type(x).__name__.
  • Resultado estranho? Espie com print(type(...)): muitos erros de iniciante são um str onde deveria haver um número.
  • type(x) == int confere o tipo exato; o tipo vai sem aspas (com aspas, a resposta é sempre False).
  • isinstance(x, int) é o jeito preferido de conferir; aceita vários tipos: isinstance(x, (int, float)).
  • Os nomes dos tipos são curtos: int, float, str, bool.
