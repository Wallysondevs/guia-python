Python Depuração

Há erros que o Python mostra na hora, com traceback e tudo. E há os piores: o programa roda até o fim, sem reclamar, e dá a resposta errada. O carrinho da lojinha da Ana cobra R$ 19,99 por uma compra de quase cem reais, e nenhuma mensagem diz por quê. Achar a causa de um defeito assim se chama depurar (em inglês, debugging: "tirar os insetos", porque defeito de programa tem o apelido de bug, "inseto"). Nesta aula você vai depurar de dois jeitos: com print e com o depurador do Python, o pdb.

Você vai aprender
  • A ideia da depuração: comparar o que o programa faz com o que você acha que ele faz.
  • A depurar com print, e o atalho f"{variavel=}".
  • A pausar o programa no meio com breakpoint() e olhar as variáveis.
  • Os comandos do pdb: l, n, s, p, c, q, e também w, b, ll e h.
  • A rodar um programa inteiro dentro do depurador com python3 -m pdb, e a examinar o programa logo depois de um erro.
  • Os enganos comuns: variável que ainda não existe, variável com nome de comando, breakpoint() esquecido no código.

A ideia: assistir ao programa em câmera lenta

Pense numa receita de bolo que deu errado: o bolo saiu salgado. Ler a receita de novo não ajuda, porque você acha que seguiu tudo certinho. O que ajuda é refazer a receita olhando cada passo: "pus o açúcar… espera, esse pote é o do sal!". O defeito está no ponto em que o que aconteceu deixa de bater com o que você esperava.

Depurar é isso. Você escolhe um ponto do programa, olha o valor das variáveis ali, e compara com o que esperava. Se bate, o defeito está mais adiante; se não bate, está antes. Há duas lupas para olhar:

LupaComo funcionaParece com…
printVocê põe prints no código e roda de novo. Eles mostram os valores enquanto o programa passaDeixar bilhetes pelo caminho
pdb / breakpoint()O programa para num ponto, e você pergunta o que quiser, avança uma linha por vez, seguePausar o filme e andar quadro a quadro

1. O programa com defeito

A função soma o carrinho e cobra R$ 15 de frete, que fica de graça acima de R$ 100:

def total_com_frete(itens, frete):
    total = 0
    for preco, quantidade in itens:
        subtotal = preco * quantidade
        total = subtotal
    if total > 100:
        frete = 0
    return total + frete


carrinho = [(27.90, 2), (8.49, 3), (4.99, 1)]
print(f"Total: R$ {total_com_frete(carrinho, 15):.2f}")

$ python3 carrinho.py
Total: R$ 19.99

Faça a conta de cabeça: 2 arroz a 27,90 dão 55,80; 3 feijão a 8,49 dão 25,47; 1 açúcar, 4,99. Os produtos somam 86,26; com o frete, 101,26. O programa disse 19,99. Nenhum erro, nenhum traceback. Onde está o problema? (Se você já viu, ótimo; finja que não, e acompanhe o método, que vale para os defeitos que não se veem a olho.)

2. Depurando com print

A primeira lupa: um print dentro do laço, mostrando tudo o que muda a cada volta. Costuma-se começar a linha com algo como DEBUG:, para distinguir da saída normal (e lembrar de apagar depois):

def total_com_frete(itens, frete):
    total = 0
    for preco, quantidade in itens:
        subtotal = preco * quantidade
        total = subtotal
        print("DEBUG:", preco, quantidade, subtotal, total)
    if total > 100:
        frete = 0
    return total + frete


carrinho = [(27.90, 2), (8.49, 3), (4.99, 1)]
print(f"Total: R$ {total_com_frete(carrinho, 15):.2f}")

$ python3 carrinho_print.py
DEBUG: 27.9 2 55.8 55.8
DEBUG: 8.49 3 25.47 25.47
DEBUG: 4.99 1 4.99 4.99
Total: R$ 19.99

Leia as três linhas comparando com o esperado. Na primeira volta, total é 55,8: certo. Na segunda, devia ser 55,8 + 25,47 = 81,27, mas é 25,47, igual ao subtotal. Achou: o total não está acumulando, está sendo trocado a cada volta. No fim ele vale só o último item (4,99), e 4,99 + 15 = 19,99.

O atalho = das f-strings

Com quatro números soltos, é fácil esquecer qual é qual. Nas f-strings, um = depois do nome da variável mostra o nome e o valor:

        print(f"{subtotal=} {total=}")

$ python3 carrinho_igual.py
subtotal=55.8 total=55.8
subtotal=25.47 total=25.47
subtotal=4.99 total=4.99
Total: R$ 19.99

f"{total=}" vira total=55.8. Funciona com qualquer expressão: f"{preco * quantidade=}" mostra preco * quantidade=55.8.

Missão: conserte o carrinho. Se quiser, ponha antes um print(f"{total=}") dentro do laço para ver o defeito acontecer; depois corrija a linha do total para que ele acumule os subtotais (e apague o print de depuração). O total certo é R$ 101.26.

Quando o print é a melhor lupa

O print é rápido, funciona em qualquer lugar e mostra a história inteira de uma vez (todas as voltas do laço). O ponto fraco: a cada pergunta nova ("e o preco?"), você edita e roda de novo, e no fim precisa apagar todos os prints. Em programas que vão continuar rodando por muito tempo, o lugar dos bilhetes é o logging, que pode ser ligado e desligado sem apagar nada.

3. Pausando o programa: breakpoint()

A segunda lupa. A função embutida breakpoint() ("ponto de parada") faz o programa parar naquela linha e abrir o pdb, o depurador do Python (Python debugger). Ali você pode perguntar o valor de qualquer variável, executar uma linha por vez e, quando quiser, deixar o programa seguir.

def total_com_frete(itens, frete):
    total = 0
    for preco, quantidade in itens:
        breakpoint()
        subtotal = preco * quantidade
        total = subtotal
    if total > 100:
        frete = 0
    return total + frete


carrinho = [(27.90, 2), (8.49, 3), (4.99, 1)]
print(f"Total: R$ {total_com_frete(carrinho, 15):.2f}")

Abaixo, a sessão de verdade, no terminal da Ana. Depois de cada (Pdb), o que ela digitou; o resto é a resposta do Python. Ela vai olhar a primeira volta do laço, deixar o programa seguir até a segunda e conferir o total:

> /home/ana/carrinho_bp.py(4)total_com_frete()
Onde o programa está parado: arquivo, linha 4, dentro da função total_com_frete.
-> breakpoint()
A próxima linha a ser executada (ela ainda não rodou).
(Pdb)
O "prompt" do depurador: ele espera um comando seu, como o >>> do modo interativo.
l
list, "listar": mostra o código em volta, com uma setinha -> na linha atual.
p preco, quantidade
print, "mostrar": calcula e mostra o valor. Primeira volta: 27,9 e 2.
n
next, "próxima": executa a linha atual e para na seguinte. Dois n e a Ana está na linha 6, com o subtotal já calculado (55,8) e o total ainda 0.
c
continue, "continuar": deixa o programa correr até a próxima parada. Como o breakpoint() está dentro do laço, ele para de novo na segunda volta.
p total → 25.47
O momento "achei!": no começo da segunda volta, o total era 55,8; depois da linha 6, virou 25,47 em vez de 81,27. A linha 6 troca o valor em vez de somar.
q
quit, "sair": encerra o depurador e o programa. No Python 3.14, quando o pdb foi aberto por um breakpoint(), ele pede confirmação: Quit anyway? [y/n] ("Sair do pdb vai matar o processo. Sair mesmo assim?"). A Ana respondeu y (yes, "sim"; n é no, "não") 3.14.
Variáveis, não comandos

No (Pdb), você pode digitar o nome de uma variável sozinho (total) e ele mostra o valor, ou até uma conta (preco * quantidade). O p é necessário quando o nome da variável é igual ao de um comando; veja em Quando dá errado. E você pode mudar uma variável no meio (total = 100) para ver o que aconteceria.

As sessões desta aula são de um terminal de verdade, onde você digita cada comando e vê a resposta. É lá que vale treinar o pdb: crie o carrinho_bp.py no seu computador e refaça a sessão da seção 3. Quando dá errado

A variável que (ainda) não existe 
$ python3 carrinho_bp.py
> /home/ana/carrinho_bp.py(4)total_com_frete()
-> breakpoint()
(Pdb) p subtotl
*** NameError: name 'subtotl' is not defined
(Pdb) subtotal
*** NameError: name 'subtotal' is not defined
(Pdb) total
0

As linhas com *** são o jeito do pdb mostrar um erro sem derrubar a sessão: você continua no (Pdb). A primeira é um erro de digitação (subtotl). A segunda é mais curiosa: subtotal está escrito certo, mas o programa está parado na linha 4, e o subtotal só é criado na linha 5, que ainda não rodou. Lembre: a linha da setinha -> é a próxima, não a última. Como consertar: confira o nome, ou avance com n até a variável ser criada.

Uma variável com nome de comando 
notas = [8, 6, 9]
soma = 0
for n in notas:
    breakpoint()
    soma += n
print(soma)

A Ana queria ver a variável n, mas n sozinho é o comando next: o programa andou uma linha. Quando o nome da variável é igual a um comando (n, s, c, l, p, q, b, w…), use p na frente: p n. Mais um motivo para dar nomes claros às variáveis: for nota in notas:.

O breakpoint() esquecido no código

A Ana mandou o programa para uma colega sem tirar o breakpoint(). Para quem roda, o programa simplesmente "trava" num (Pdb) que ela não pediu. E se o programa roda sem ninguém no teclado (com a entrada vindo de um arquivo, por exemplo), o pdb lê o fim da entrada como "sair":

$ python3 carrinho_bp.py < /dev/null
> /home/ana/carrinho_bp.py(4)total_com_frete()
-> breakpoint()
(Pdb)
Quitting pdb will kill the process. Quit anyway? [y/n]
$ echo $?
1

O programa terminou no meio, sem mostrar o total, com o código de saída 1 (falha). Como consertar: apague os breakpoint() antes de entregar o programa (procure por eles: grep -n breakpoint *.py). E, para rodar sem as paradas sem editar nada, existe a variável de ambiente PYTHONBREAKPOINT=0, que desliga todos os breakpoint():

$ PYTHONBREAKPOINT=0 python3 carrinho_bp.py
Total: R$ 19.99
Consertar o sintoma em vez da causa

Não é uma mensagem de erro, mas é o engano mais comum de quem depura. Com o carrinho dando 19,99, dá vontade de "ajustar" o resultado (somar a diferença no fim, mudar o frete) até sair o número certo para aquele carrinho. O próximo carrinho vai dar errado de novo. Depurar é achar a linha em que o valor deixa de ser o esperado (a linha 6, total = subtotal) e consertar ali.

Missão final: as vogais da Ana

Missão: a função devia contar as vogais de "Ana Beatriz" (A, a, e, a, i: são 5), mas diz 4. Ponha um print de depuração dentro do for (por exemplo, print(f"{letra=} {total=}")), descubra qual letra não está sendo contada e conserte a função. Depois, apague o print de depuração.

def contar_vogais(texto):
    total = 0
    for letra in texto:
        if letra in "aeiou":
            total += 1
    return total


print("Vogais:", contar_vogais("Ana Beatriz"))

def contar_vogais(texto):
    total = 0
    for letra in texto:
        if letra.lower() in "aeiou":
            total += 1
    return total


print("Vogais:", contar_vogais("Ana Beatriz"))

O print mostra a letra 'A' passando sem o total mudar: "A" maiúsculo não está em "aeiou". Há dois consertos: letra.lower() in "aeiou" ou letra in "aeiouAEIOU". E se o texto fosse "Érica"? Pense no que o print mostraria.

Resumo

  • Depurar é comparar, ponto a ponto, o que o programa faz com o que você espera, até achar a linha em que os dois se separam.
  • print mostra a história inteira; print(f"{x=}") põe o nome junto. Apague os prints de depuração no fim.
  • breakpoint() pausa o programa e abre o pdb. A linha da setinha -> é a próxima a rodar.
  • Comandos: l lista, n próxima linha, s entra na função, p mostra um valor, c continua, q sai (no 3.14, confirme com y); e w, b, ll, h.
  • python3 -m pdb programa.py roda tudo no depurador; se o programa quebrar, ele para no erro (post mortem).
  • Variável com nome de comando? Use p. Não esqueça breakpoint() no código; PYTHONBREAKPOINT=0 desliga todos.
