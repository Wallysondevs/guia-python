Python __init__ e self

Na aula Classes e Objetos, a Ana criava um produto vazio e depois pendurava os dados um por um: cafe = Produto(), cafe.nome = "Café", cafe.preco = 18.90. Três linhas por produto, e se ela esquecesse uma, o programa quebrava lá na frente com AttributeError. Nesta aula você vai escrever o __init__, o trecho da classe que roda sozinho toda vez que um objeto nasce e já deixa tudo preenchido. Com ele, criar um produto vira uma linha: Produto("Café", 18.90). E vai conhecer o self, a palavrinha que aparece em todo método e que quer dizer "o próprio objeto".

Você vai aprender
  • A escrever o __init__, para que todo objeto já nasça com os seus dados.
  • O que é o self, e por que self.nome = nome tem dois "nome".
  • Quando o __init__ roda, e quem passa o self para ele.
  • A escrever o primeiro método, mostrar(self), e o que cafe.mostrar() faz por baixo.
  • Valores padrão (estoque=0) e argumentos nomeados no __init__.
  • Os erros reais: o self esquecido, argumentos faltando ou sobrando, o __int__ digitado errado e o self. esquecido.

A ideia: a ficha com os campos obrigatórios

Na lojinha da Ana, o cadastro de um produto novo é uma ficha com campos obrigatórios: ninguém cadastra um produto sem nome e sem preço. A pessoa do caixa preenche os campos na hora em que a ficha é criada, e a ficha já vai para o arquivo completa.

O __init__ é essa hora do preenchimento. O nome vem de initialize, "inicializar": é o que acontece logo no começo da vida do objeto. E o self (em inglês, "si mesmo", "o próprio") é a ficha que está sendo preenchida agora. Quando o __init__ diz self.nome = nome, ele está dizendo: "no campo nome desta ficha aqui, escreva o nome que me deram".

1. O primeiro __init__

class Produto:
    def __init__(self, nome, preco):
        self.nome = nome
        self.preco = preco


cafe = Produto("Café", 18.90)
pao = Produto("Pão de forma", 9.50)

print(cafe.nome, cafe.preco)
print(pao.nome, pao.preco)
def __init__
Uma função escrita dentro da classe (recuada 4 espaços). Uma função que mora numa classe se chama método. O nome tem dois sublinhados antes e dois depois: __init__. Os programadores leem "dunder init" (de double underscore, "sublinhado duplo"). Nomes assim são especiais: o Python os chama sozinho em certos momentos.
(self, nome, preco)
Os parâmetros. O primeiro é sempre o self, o objeto que está nascendo. Depois vêm os dados que quem cria o produto precisa informar.
self.nome = nome
Lido da direita para a esquerda: pegue o nome que chegou como parâmetro e guarde no atributo nome do objeto (self.nome). Os dois "nome" são coisas diferentes: o da direita é o parâmetro, que some quando o __init__ termina; o da esquerda é o atributo, que fica guardado no objeto.
self.preco = preco
O mesmo, para o preço.
Produto("Café", 18.90)
Cria um produto passando os dados entre os parênteses, na ordem dos parâmetros depois do self: "Café" vai para nome, 18.90 vai para preco. Repare que ninguém passa o self: o Python passa sozinho.
$ python3 init1.py
Café 18.9
Pão de forma 9.5

O resultado é o mesmo da aula anterior, mas cada produto agora é criado numa linha só, e não tem como nascer um produto sem nome ou sem preço: o Python não deixa (você vai ver o erro em Quando dá errado).

2. Quando o __init__ roda?

Você nunca escreve cafe.__init__(…). Quem chama o __init__ é o próprio Python, no momento em que o objeto é criado. Um print dentro dele mostra a hora exata:

class Produto:
    def __init__(self, nome, preco):
        print(f"__init__ rodou para: {nome}")
        self.nome = nome
        self.preco = preco


print("Antes de criar")
cafe = Produto("Café", 18.90)
print("Entre um e outro")
pao = Produto("Pão de forma", 9.50)
print("Depois de criar")

$ python3 quando.py
Antes de criar
__init__ rodou para: Café
Entre um e outro
__init__ rodou para: Pão de forma
Depois de criar

O __init__ roda uma vez para cada objeto criado, bem na linha do Produto(…). Quando você escreve Produto("Café", 18.90), o Python faz três coisas, nesta ordem:

  1. Cria um objeto Produto novo, ainda vazio (uma ficha em branco).
  2. Chama o __init__ passando o objeto novo como self, mais os seus dados: é como se fosse __init__(objeto_novo, "Café", 18.90). O __init__ preenche a ficha.
  3. Entrega o objeto pronto, que vai para a variável cafe.

3. O self é o próprio objeto

Se o self é o objeto que está nascendo, então ele e o cafe têm de ser a mesma coisa. Dá para conferir pelo endereço da memória (aquele 0x… da aula passada):

class Produto:
    def __init__(self, nome, preco):
        print("self é:", self)
        self.nome = nome
        self.preco = preco


cafe = Produto("Café", 18.90)
print("cafe é:", cafe)

$ python3 self_mesmo.py
self é: <__main__.Produto object at 0x7f933bd90590>
cafe é: <__main__.Produto object at 0x7f933bd90590>

O mesmo endereço. Dentro do __init__, o objeto se chama self; fora dele, depois de pronto, ele se chama cafe. São dois nomes para um objeto só. (No seu computador o número será outro, mas os dois vão ser iguais entre si.)

Por que o Python precisa disso? Porque a classe é uma só, e os objetos são muitos. O mesmo __init__ preenche o café, o pão e o leite. O self é a forma de o código da classe dizer "este objeto, aquele que está sendo cuidado agora", sem saber de antemão qual é.

4. O primeiro método: o objeto sabe fazer coisas

O __init__ é um método que o Python chama sozinho. Você também pode escrever os seus métodos, para o objeto fazer coisas. Todo método recebe o self como primeiro parâmetro, e é por ele que o método enxerga os dados do objeto:

class Produto:
    def __init__(self, nome, preco):
        self.nome = nome
        self.preco = preco

    def mostrar(self):
        print(f"{self.nome}: R$ {self.preco:.2f}")


cafe = Produto("Café", 18.90)
pao = Produto("Pão de forma", 9.50)

cafe.mostrar()
pao.mostrar()
Produto.mostrar(cafe)
def mostrar(self):
Um método novo, no mesmo recuo do __init__ (dentro da classe), separado dele por uma linha em branco. Ele só precisa do self: tudo de que precisa já está guardado no objeto.
self.nome, self.preco
Dentro do método, os dados do objeto são lidos pelo self. O :.2f mostra o preço com duas casas (aula f-strings).
cafe.mostrar()
Chama o método no objeto cafe. Os parênteses estão vazios, e mesmo assim o método recebe o self: o Python põe o cafe lá.
Produto.mostrar(cafe)
O que o Python faz por baixo: chama o mostrar da classe passando o cafe como self. Ninguém escreve assim no dia a dia, mas é o que explica o self.
$ python3 metodo.py
Café: R$ 18.90
Pão de forma: R$ 9.50
Café: R$ 18.90                     « Produto.mostrar(cafe): o mesmo que cafe.mostrar()

Esta é a regra que você precisa guardar:

Você escreveO Python fazDentro do método, self é…
cafe.mostrar()Produto.mostrar(cafe)o cafe
pao.mostrar()Produto.mostrar(pao)o pao
Produto("Café", 18.90)__init__(novo, "Café", 18.90)o objeto que está nascendo

O que vem antes do ponto vira o self. É por isso que o mesmo método mostrar mostra o café numa chamada e o pão na outra. Métodos têm uma aula inteira, a próxima: Atributos e Métodos.

5. Valores padrão e argumentos nomeados

O __init__ é uma função, então tudo o que você aprendeu na aula Valores Padrão e Argumentos Nomeados vale aqui. Um produto recém-cadastrado pode ainda não ter estoque: o estoque vale 0 se ninguém disser nada.

class Produto:
    def __init__(self, nome, preco, estoque=0):
        self.nome = nome
        self.preco = preco
        self.estoque = estoque


cafe = Produto("Café", 18.90, 12)
leite = Produto("Leite", 6.50)
pao = Produto(nome="Pão de forma", preco=9.50, estoque=30)

print(cafe.nome, cafe.estoque)
print(leite.nome, leite.estoque)
print(pao.nome, pao.estoque)

$ python3 padrao.py
Café 12
Leite 0                            « não disse o estoque: ficou o padrão
Pão de forma 30                    « argumentos nomeados: dá para ler sem decorar a ordem

Nem todo atributo vem de um parâmetro

O __init__ pode criar atributos calculados, ou com um valor inicial fixo. A ficha de um aluno já nasce com a média calculada e com zero faltas:

class Aluno:
    def __init__(self, nome, nota1, nota2):
        self.nome = nome
        self.nota1 = nota1
        self.nota2 = nota2
        self.media = (nota1 + nota2) / 2
        self.faltas = 0


bia = Aluno("Bia", 8.0, 9.5)
print(bia.nome, bia.media, bia.faltas)
print(vars(bia))

$ python3 calculado.py
Bia 8.75 0
{'nome': 'Bia', 'nota1': 8.0, 'nota2': 9.5, 'media': 8.75, 'faltas': 0}

O vars(bia) mostra os cinco atributos que o __init__ criou. Uma boa prática: crie todos os atributos do objeto dentro do __init__, mesmo os que começam vazios ou zerados. Assim, quem lê a classe descobre num lugar só quais dados todo objeto tem.

Funciona: o atributo se chama o que estiver depois de self.. O parâmetro n só existe enquanto o __init__ roda; por isso cafe.n não existe. Mas usar o mesmo nome (self.nome = nome) é o costume, e é mais claro: quem lê sabe na hora qual parâmetro vira qual atributo.

O self é só um nome

class Produto:
    def __init__(eu, nome, preco):
        eu.nome = nome
        eu.preco = preco


cafe = Produto("Café", 18.90)
print(cafe.nome)

$ python3 outro_nome.py
Café

Também funciona. Para o Python, o que importa é a posição: o primeiro parâmetro de um método recebe o objeto, chame-se ele como for. Mas todo mundo usa self: os editores de código, os colegas e os tutoriais esperam esse nome. Trocar só confunde.

Quando dá errado

Esquecer o self no método: takes 0 positional arguments but 1 was given

É o erro mais comum de quem está começando com classes:

class Produto:
    def __init__(self, nome, preco):
        self.nome = nome
        self.preco = preco

    def mostrar():
        print("Um produto da lojinha")


cafe = Produto("Café", 18.90)
cafe.mostrar()

$ python3 sem_self.py
Traceback (most recent call last):
  File "/home/ana/sem_self.py", line 11, in <module>
    cafe.mostrar()
    ~~~~~~~~~~~~^^
TypeError: Produto.mostrar() takes 0 positional arguments but 1 was given

Linha por linha:

  • File "/home/ana/sem_self.py", line 11: o erro estourou na linha 11, a da chamada cafe.mostrar(), e não na linha 6, onde está o engano. O Python só descobre o problema quando tenta usar o método.
  • ~~~~~~~~~~~~^^: os tils marcam o que foi chamado (cafe.mostrar) e os ^^ marcam os parênteses da chamada, onde o problema aconteceu.
  • TypeError: "erro de tipo", usado quando uma função é chamada do jeito errado.
  • Produto.mostrar() takes 0 positional arguments but 1 was given: "o Produto.mostrar() recebe 0 argumentos, mas foi dado 1".

"Mas eu não passei nada!", pensa a Ana. Passou, sim, sem ver: cafe.mostrar() vira Produto.mostrar(cafe). O Python entregou o cafe, e o def mostrar(): não tinha onde recebê-lo. Como consertar: def mostrar(self):. Todo método comum começa com self.

"Produto() não recebe argumentos". Faltou um i: __int__ (que existe, mas serve para outra coisa, converter o objeto em número inteiro).   • O __init__ (dois sublinhados de cada lado) roda sozinho toda vez que um objeto nasce, e serve para preencher os dados dele.
  • Produto("Café", 18.90) cria um objeto vazio, chama __init__(novo, "Café", 18.90) e entrega o objeto pronto.
  • self é o próprio objeto: dentro do __init__, o que está nascendo; num método, o que veio antes do ponto. cafe.mostrar() é o mesmo que Produto.mostrar(cafe).
  • self.nome = nome guarda o parâmetro no objeto. Sem o self., nada é guardado.
  • Todo método comum tem self como primeiro parâmetro. Sem ele: takes 0 positional arguments but 1 was given.
  • Nas mensagens de argumentos, a conta inclui o self. Produto() takes no arguments quer dizer que o __init__ não existe ou está com o nome errado.
  • Valores padrão e argumentos nomeados funcionam no __init__ como em qualquer função. Crie todos os atributos dentro dele.
