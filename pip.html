Python pip

O Python já vem com muita coisa pronta: math, random, datetime, json… É a biblioteca padrão, que você conheceu na aula Módulos e import. Mas o mundo do Python é muito maior do que isso: milhares de pessoas escrevem módulos e os deixam disponíveis de graça, para qualquer um usar. Para trazer esses módulos para o seu computador existe o pip, o instalador de pacotes do Python. Nesta aula você vai usá-lo de verdade, no terminal da Ana, e vai entender por que a primeira tentativa, no Ubuntu, sempre dá erro.

Você vai aprender
  • O que é um pacote e o que é o PyPI, a "loja" de onde o pip baixa.
  • Por que o pip install do Ubuntu responde externally-managed-environment, e o que é a PEP 668.
  • As três saídas: o pacote do apt, o ambiente virtual e (para programas) o pipx.
  • A instalar, listar, ver detalhes, atualizar e remover pacotes: pip install, list, show, uninstall.
  • A anotar os pacotes do projeto num requirements.txt com pip freeze, e a reinstalar tudo com pip install -r.
  • Os erros reais: nome digitado errado, sem internet, esqueceu de ativar o ambiente.
Esta é uma aula de terminal

O pip é um programa que roda no terminal do seu computador, não dentro de um programa Python. Por isso, quase tudo aqui é mostrado em janelas de terminal, com o que o Ubuntu da Ana respondeu de verdade. O editor do guia (o "Experimente") não instala pacotes; as caixas desta aula treinam o que dá para treinar nele: ler um requirements.txt e reconhecer o erro de pacote que falta.

A ideia: a loja de aplicativos do Python

Pense no celular da Ana. Ele já vem com alguns aplicativos de fábrica: a câmera, o relógio, a calculadora. Quando ela quer outro (um app de receitas, um jogo), abre a loja de aplicativos, procura pelo nome e toca em "instalar". Ninguém precisa escrever o app; alguém já escreveu e deixou na loja.

No Python é igual:

No celularNo Python
Os apps de fábricaA biblioteca padrão: math, random, json… (já vem com o Python)
Um app da lojaUm pacote (em inglês, package): um ou mais módulos que outra pessoa escreveu
A loja de aplicativosO PyPI (Python Package Index, "índice de pacotes do Python"), no site pypi.org, com centenas de milhares de pacotes
O botão "instalar"O comando pip install nome-do-pacote

O nome pip é uma brincadeira recursiva em inglês: "pip installs packages", "o pip instala pacotes". Nesta aula, o pacote de exemplo é o requests ("pedidos"), um dos mais usados do mundo: ele deixa um programa Python conversar com sites da internet com uma linha só.

1. O pip já está aí?

No Ubuntu 26.04 da Ana, o pip veio instalado junto com o Python (é o pacote python3-pip do Ubuntu). Para conferir, peça a versão:

$ python3 --version
Python 3.14.4
$ pip --version
pip 25.1.1 from /usr/lib/python3/dist-packages/pip (python 3.14)
$ pip3 --version
pip 25.1.1 from /usr/lib/python3/dist-packages/pip (python 3.14)
pip 25.1.1
A versão do pip. Ele tem as versões dele, separadas das do Python.
from /usr/lib/python3/dist-packages/pip
"De onde" ele veio: a pasta do sistema onde o Ubuntu guarda os módulos Python que ele instalou.
(python 3.14)
Para qual Python esse pip instala. Isso importa: cada Python tem o seu pip.

pip e pip3 são o mesmo programa (o "3" é de Python 3). Existe ainda uma terceira forma, que você vai ver muito em tutoriais: python3 -m pip. O -m quer dizer "rode o módulo": você pede ao próprio python3 que rode o pip dele. A vantagem é não ter dúvida de qual Python vai receber o pacote. Para ver o que já está instalado, use list ("listar"):

$ python3 -m pip list
Package           Version
----------------- ---------------
command-not-found 0.3
packaging         26.0
pip               25.1.1
python-apt        3.1.0+ubuntu1.1
wheel             0.46.3

Poucos pacotes, e todos foram instalados pelo Ubuntu, não pela Ana. O command-not-found, por exemplo, é o programa que sugere "você quis dizer python3?" quando alguém digita python. Guarde essa informação: o próprio Ubuntu usa o Python para fazer o trabalho dele.

Não tem o pip?

Se o seu terminal responder Comando 'pip' não encontrado, o pacote do Ubuntu não está instalado. Instale com sudo apt install python3-pip python3-venv (o sudo pede a sua senha; detalhes na aula Instalar o Python).

A Ana quer usar o requests. Ela confere que ele não existe ainda (o Python responde com um ModuleNotFoundError, "módulo não encontrado") e manda instalar:

$ python3 -c "import requests"
Traceback (most recent call last):
  File "<string>", line 1, in <module>
    import requests
ModuleNotFoundError: No module named 'requests'
$ pip install requests
error: externally-managed-environment

    python3-xyz, where xyz is the package you are trying to
    install.

    If you wish to install a non-Debian-packaged Python package,
    create a virtual environment using python3 -m venv path/to/venv.
    Then use path/to/venv/bin/python and path/to/venv/bin/pip. Make

    If you wish to install a non-Debian packaged Python application,

    See /usr/share/doc/python3.14/README.venv for more information.

hint: See PEP 668 for the detailed specification.

(O python3 -c "…" roda um pedacinho de código direto do terminal, sem criar arquivo: o -c é de "comando".) O pip se recusou a instalar. Não é defeito: é de propósito. A mensagem está em inglês; leia com calma, parte por parte:

error: externally-managed-environment
"Erro: ambiente gerenciado por fora." Este Python pertence ao sistema, e quem cuida dos pacotes dele é outro programa (o apt do Ubuntu), não o pip.
try apt install python3-xyz
Primeira saída: "tente o apt install python3-xyz, onde xyz é o pacote que você quer". Ou seja, peça o pacote ao Ubuntu.
create a virtual environment using python3 -m venv
Segunda saída: "crie um ambiente virtual" e instale lá dentro, à vontade.
pipx install xyz
Terceira saída, para quando o pacote é um programa que você quer usar no terminal (e não um módulo para importar).
--break-system-packages
"Quebrar os pacotes do sistema": uma opção que força a instalação. O nome já avisa o risco.
hint: See PEP 668
"Dica: veja a PEP 668", o documento que criou essa regra.

Mesmo com pip3, com python3 -m pip ou com pip install --user requests (que instalaria só para a Ana), a resposta é a mesma, letra por letra.

Por que o Ubuntu bloqueia: a PEP 668

Uma PEP (Python Enhancement Proposal, "proposta de melhoria do Python") é um documento público em que a comunidade decide uma regra do Python. A PEP 668 resolveu um problema antigo: o mesmo Python servia ao mesmo tempo para os programas da pessoa e para os programas do sistema. Lembra do command-not-found e do python-apt na lista lá de cima? São ferramentas do Ubuntu escritas em Python. Se a Ana instalasse com o pip uma versão diferente de um módulo que elas usam, uma atualização do sistema poderia parar de funcionar, e ninguém saberia por quê.

A solução: o sistema coloca um arquivo chamado EXTERNALLY-MANAGED na pasta do Python, e o pip, ao encontrá-lo, se recusa a mexer ali. A mensagem que você leu vem desse arquivo:

$ cat /usr/lib/python3.14/EXTERNALLY-MANAGED
[externally-managed]
Error=To install Python packages system-wide, try apt install
 python3-xyz, where xyz is the package you are trying to
 install.

 If you wish to install a non-Debian-packaged Python package,
 create a virtual environment using python3 -m venv path/to/venv.
 Then use path/to/venv/bin/python and path/to/venv/bin/pip. Make
 sure you have python3-full installed.

 If you wish to install a non-Debian packaged Python application,
 it may be easiest to use pipx install xyz, which will manage a
 virtual environment for you. Make sure you have pipx installed.

 See /usr/share/doc/python3.14/README.venv for more information.
Em outros sistemas

O Debian (desde a versão 12) e outras distribuições fazem o mesmo; o Ubuntu, desde a 23.04. Por isso tantos tutoriais antigos mandam rodar só pip install e, no seu computador, dá esse erro. No Windows e no macOS com o Python baixado do python.org, não há esse arquivo e o pip install funciona direto; mesmo assim, a boa prática é a mesma de todo lugar: um ambiente virtual por projeto.

"Você é root?" (o administrador). O certo é sudo apt install python3-requests, que pede a senha da Ana e instala. (O laboratório do guia não tem sudo, então essa última linha não aparece aqui rodando; ela é a mesma da aula Instalar o Python.)

4. Saída 2: o ambiente virtual (o jeito de todo dia)

Um ambiente virtual é uma pasta com uma "cópia" particular do Python, só para um projeto. Lá dentro, o pip é seu: instala o que quiser, na versão que quiser, sem sudo e sem encostar no Python do sistema. Ele tem uma aula só para ele, Ambientes Virtuais (venv); aqui você só precisa de três comandos para começar. A Ana cria a pasta do projeto da lojinha, cria o ambiente e o ativa:

$ mkdir loja
$ cd loja
$ python3 -m venv .venv
$ source .venv/bin/activate
(.venv) ana@notebook:~/loja$ which pip
/home/ana/loja/.venv/bin/pip
(.venv) ana@notebook:~/loja$ pip list
Package Version
------- -------
pip     25.1.1
python3 -m venv .venv
Cria o ambiente virtual numa pasta chamada .venv, dentro do projeto.
source .venv/bin/activate
Ativa o ambiente: a partir daqui, python e pip são os de dentro da .venv.
(.venv)
O começo do prompt mudou: é o terminal avisando que o ambiente está ativo.
which pip
"Qual pip?": agora é o que está em /home/ana/loja/.venv/bin/.
pip list
Um ambiente novo vem vazio: só o próprio pip.

7. pip freeze e o requirements.txt

Daqui a um mês, a Ana vai querer rodar a lojinha no computador da Bia. Como a Bia vai saber quais pacotes instalar, e em quais versões? O pip freeze ("congelar") imprime a lista exata, num formato que o próprio pip entende:

(.venv) ana@notebook:~/loja$ pip freeze
certifi==2026.7.22
charset-normalizer==3.5.2
idna==3.20
requests==2.34.2
urllib3==2.8.0
(.venv) ana@notebook:~/loja$ pip freeze > requirements.txt
(.venv) ana@notebook:~/loja$ cat requirements.txt
certifi==2026.7.22
charset-normalizer==3.5.2
idna==3.20
requests==2.34.2
urllib3==2.8.0
requests==2.34.2
Uma linha por pacote: o nome, dois sinais de igual e a versão exata. É uma "foto" do ambiente.
> requirements.txt
O > do terminal manda a saída para um arquivo em vez da tela. requirements.txt ("requisitos") é o nome que todo projeto Python usa para essa lista.

Do outro lado, a Bia cria o ambiente dela e instala tudo de uma vez com -r (de requirement, "leia a lista deste arquivo"). Para mostrar, a Ana tira o requests do ambiente e pede a lista de volta:

O que vai para o git, o que não vai

O requirements.txt é pequeno e é a "receita" do projeto: guarde-o junto com o código. A pasta .venv é grande e pode ser recriada a qualquer momento a partir da receita: não a copie para outro computador nem a coloque no git.

Um requirements.txt é só um arquivo de texto, então um programa Python consegue lê-lo como qualquer outro (a aula Lendo Arquivos mostra como). Experimente:

A mais nova: --upgrade

Remover: pip uninstall

uninstall ("desinstalar") mostra o que vai apagar e pergunta antes. Responda y (de yes, "sim"):

(.venv) ana@notebook:~/loja$ pip uninstall requests
Found existing installation: requests 2.34.2
Uninstalling requests-2.34.2:
  Would remove:
    /home/ana/loja/.venv/lib/python3.14/site-packages/requests-2.34.2.dist-info/*
    /home/ana/loja/.venv/lib/python3.14/site-packages/requests/*
Proceed (Y/n)? y
  Successfully uninstalled requests-2.34.2

"Would remove" é "removeria"; "Proceed (Y/n)?", "continuar?". O Y maiúsculo indica a resposta padrão: só apertar Enter também vale como sim. Com -y (como na seção anterior), o pip não pergunta. Repare que só o requests saiu: as dependências que vieram com ele continuam lá.

Quando dá errado

error: externally-managed-environment

Você já viu na seção 2: é o pip install fora de um ambiente virtual, no Python do sistema. Como consertar: crie e ative um ambiente (python3 -m venv .venv e source .venv/bin/activate) e repita o comando; ou use sudo apt install python3-nome.

O nome do pacote digitado errado 
(.venv) ana@notebook:~/loja$ pip install requets
ERROR: Could not find a version that satisfies the requirement requets (from versions: none)
ERROR: No matching distribution found for requets

"Não achei uma versão que atenda ao requisito requets (versões: nenhuma)." O pip não sugere o nome certo: ele só sabe que não existe nenhum pacote com esse nome no PyPI. Como consertar: confira a grafia (era requests, com s antes do t). Na dúvida, procure o nome exato em pypi.org.

Cuidado com nomes parecidos

Qualquer pessoa pode publicar no PyPI, e já houve casos de pacotes maliciosos com nomes quase iguais aos famosos, esperando um erro de digitação. Copie o nome da página oficial do pacote e desconfie de nomes com uma letra trocada.

apt install sem sudo

Não é possível adquirir a trava da interface do dpkg (…), você é root?: instalar pacotes do Ubuntu é tarefa de administrador (seção 3). Como consertar: sudo apt install python3-requests. E nunca o contrário: não use sudo pip install; o pip com sudo mexeria justamente na pasta que a PEP 668 protege.

O ModuleNotFoundError é um erro como outro qualquer, e um programa pode se preparar para ele com try e except (aula try e except): em vez de explodir, ele avisa o que falta instalar. O módulo graficos_da_padaria abaixo não existe em lugar nenhum, de propósito.

Missão: rode e veja o ModuleNotFoundError. Depois, coloque o import dentro de um try e, no except ModuleNotFoundError as erro:, mostre Instale com: pip install graficos_da_padaria (o nome do módulo que faltou fica em erro.name).

import graficos_da_padaria

print("Gráficos prontos!")

try:
    import graficos_da_padaria
    print("Gráficos prontos!")
except ModuleNotFoundError as erro:
    print(f"Falta o módulo {erro.name}.")
    print(f"Instale com: pip install {erro.name}")

No computador de verdade, quem faz essa conta é o próprio pip install -r requirements.txt: ele pula o que já está lá ("Requirement already satisfied") e instala só o que falta.

Resumo

  • Um pacote é código que outra pessoa escreveu; o PyPI (pypi.org) é a loja; o pip é o instalador.
  • No Ubuntu (e no Debian, e em outras distribuições), pip install no Python do sistema dá externally-managed-environment: é a PEP 668 protegendo as ferramentas do sistema.
  • As saídas: ambiente virtual (o jeito de todo dia), sudo apt install python3-nome (pacotes famosos, na versão do Ubuntu) e pipx (programas de terminal). Evite --break-system-packages e sudo pip.
  • No ambiente ativo: pip install, pip list, pip show, pip install --upgrade, pip uninstall.
  • pip freeze > requirements.txt grava a receita do projeto; pip install -r requirements.txt refaz o ambiente em outro lugar.
  • ModuleNotFoundError depois de instalar quase sempre é o ambiente desativado: olhe se o prompt começa com (.venv).
