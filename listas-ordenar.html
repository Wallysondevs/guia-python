Python Ordenando Listas

A professora quer a chamada em ordem alfabética. A Ana quer ver as notas da maior para a menor. O caixa quer os preços do mais barato ao mais caro. Pôr uma lista em ordem (em inglês, sort, "ordenar") é uma das coisas mais úteis que o Python faz, e ele faz em uma linha. Mas há detalhes que pegam todo mundo: a diferença entre sort() e sorted(), as maiúsculas que vêm antes das minúsculas e os nomes com acento que vão parar no fim da lista.

Você vai aprender
  • A ordenar a própria lista com sort(), e a criar uma lista nova ordenada com sorted().
  • A ordem decrescente com reverse=True, e a inverter uma lista com reverse(), reversed() e [::-1].
  • Como o Python compara textos, e por que "Zé" vem antes de "ana" e o "Álvaro" vai para o fim.
  • A escolher o critério com key: key=str.lower, key=len, key=int.
  • Os erros reais: lista = lista.sort() (a lista vira None) e a lista com números e textos misturados.

A ideia: arrumar as fichas, ou tirar uma cópia arrumada

A professora tem as fichas dos alunos numa caixa, fora de ordem. Ela pode fazer duas coisas:

  • Arrumar as fichas na própria caixa. Depois disso, a ordem antiga se perdeu. É o lista.sort().
  • Deixar a caixa como está e escrever uma folha nova, com os nomes em ordem. A caixa original continua igual. É o sorted(lista).

Os dois põem em ordem do mesmo jeito; a diferença é o que acontece com a lista original.

3. Como o Python compara textos

Com números, "em ordem" é óbvio. Com textos, o Python compara letra por letra, da esquerda para a direita, como no dicionário. Só que ele não usa o alfabeto que você aprendeu na escola: cada caractere tem um número (o código Unicode), e a ordem é a desses números. A função ord() mostra o número de um caractere:

>>> ord("A")
65
>>> ord("Z")
90
>>> ord("a")
97
>>> ord("Á")
193
>>> "Zé" < "ana"
True
>>> "Álvaro" < "Bruno"
False

Todas as maiúsculas sem acento (65 a 90) vêm antes de todas as minúsculas (97 a 122), e as letras com acento vêm depois de todas elas (o Á é o 193). Por isso "Zé" é "menor" que "ana", e "Álvaro" é "maior" que "Bruno". Duas consequências que você precisa conhecer:

Maiúsculas antes das minúsculas

nomes = ["bruno", "Davi", "ana", "Carla"]
print(sorted(nomes))
print(sorted(nomes, key=str.lower))

$ python3 maiusculas.py
['Carla', 'Davi', 'ana', 'bruno']
['ana', 'bruno', 'Carla', 'Davi']

Na primeira linha, os nomes com maiúscula vieram antes, e os com minúscula depois: não é a ordem que uma pessoa espera. A segunda linha resolve com o key, que você vai ver na seção 4: key=str.lower quer dizer "compare como se tudo estivesse em minúsculas". Repare que os nomes continuam escritos como estavam; só a comparação ignora as maiúsculas.

O Álvaro vai para o fim

nomes = ["Bruno", "Álvaro", "Ana", "Carla", "Érica", "Eduardo"]
print(sorted(nomes))

$ python3 acentos.py
['Ana', 'Bruno', 'Carla', 'Eduardo', 'Álvaro', 'Érica']

O Álvaro, que deveria ser o primeiro da chamada, foi para depois do Eduardo, junto com a Érica. Não é um erro do Python: é a regra dos números dos caracteres. O Á (193) vem depois de qualquer letra sem acento.

Para ordenar como no dicionário: locale

O Python tem um jeito de comparar textos pelas regras de um idioma: o módulo locale (aula Módulos e import) e a função locale.strxfrm, usada como key. No terminal da Ana, com o português do Brasil instalado:

import locale

locale.setlocale(locale.LC_COLLATE, "pt_BR.UTF-8")
nomes = ["Bruno", "Álvaro", "Ana", "Carla", "Érica", "Eduardo"]
print(sorted(nomes, key=locale.strxfrm))

$ python3 acentos_locale.py
['Álvaro', 'Ana', 'Bruno', 'Carla', 'Eduardo', 'Érica']

Agora o Álvaro abre a chamada. Mas esse resultado depende dos idiomas instalados no computador: se o pt_BR.UTF-8 não estiver instalado, o setlocale para o programa com locale.Error: unsupported locale setting ("configuração de idioma não suportada"). E no editor do guia, que roda no navegador, o mesmo programa roda sem erro, mas sai na ordem do sorted comum, com o Álvaro no fim. Por isso, neste guia, fica só como nota.

4. Escolhendo o critério: key

O key ("chave") diz ao Python: "antes de comparar, passe cada item por esta função, e compare o resultado". Os itens em si não mudam; só a régua usada para comparar.

key=str.lower
Compara pela versão em minúsculas de cada texto: "Davi" é comparado como "davi".
key=len
Compara pelo tamanho de cada item.
key=int
Compara pelo número que o texto representa.

Repare que depois do key= vai o nome da função, sem parênteses: key=len, e não key=len(). Você não está chamando a função; está dizendo ao sort qual função ele deve chamar, item por item.

Pelo tamanho

compras = ["café", "arroz", "pão", "feijão", "sal"]
print(sorted(compras, key=len))

$ python3 tamanho.py
['pão', 'sal', 'café', 'arroz', 'feijão']

Do item mais curto (3 letras) para o mais longo (6). O pão e o sal têm o mesmo tamanho, e ficaram na ordem em que já estavam na lista: quando dois itens "empatam", o Python mantém a ordem original entre eles.

Números guardados como texto

As senhas da fila do banco chegaram como texto. Ordenadas assim, o resultado é estranho:

senhas = ["10", "9", "2", "100"]
print(sorted(senhas))
print(sorted(senhas, key=int))

$ python3 texto_numero.py
['10', '100', '2', '9']
['2', '9', '10', '100']

Como textos, eles são comparados caractere por caractere: "10" começa com "1", que vem antes de "2", então "10" e "100" ficam antes do "2". Com key=int, cada texto é comparado como o número que representa, e a ordem fica certa. (Os itens continuam sendo textos: repare nas aspas.)

Listas dentro de listas

Quando os itens são listas, o Python compara o primeiro item de cada uma; se empatar, o segundo, e assim por diante:

>>> turma = [["Davi", 7.0], ["Ana", 9.5], ["Carla", 8.0]]
>>> sorted(turma)
[['Ana', 9.5], ['Carla', 8.0], ['Davi', 7.0]]

Ficou em ordem de nome. Para ordenar pela nota (o segundo item), o key precisa de uma função que pegue o item 1 de cada par. Você vai aprender a escrever essas funções nas aulas Funções e lambda.

Missão: alguns nomes foram digitados em minúsculas e a chamada saiu fora de ordem. Use o key para ordenar sem ligar para maiúsculas.

chamada = ["carla", "Davi", "ana", "Bruno"]
print(sorted(chamada))

chamada = ["carla", "Davi", "ana", "Bruno"]
print(sorted(chamada, key=str.lower))

5. Invertendo a ordem (sem ordenar)

Às vezes você não quer ordenar: quer só a lista de trás para frente, como ela está. Há três jeitos:

fila = ["Ana", "Bruno", "Carla"]
fila.reverse()
print(fila)
fila = ["Ana", "Bruno", "Carla"]
print(fila[::-1])
print(list(reversed(fila)))
for nome in reversed(fila):
    print(nome)
print(fila)

Se você mostrar o reversed(fila) direto, não aparece uma lista, e sim um objeto que entrega os itens quando alguém pede (o número no fim é um endereço da memória, e muda a cada execução):

>>> fila = ["Ana", "Bruno", "Carla"]

reverse() não é "ordem decrescente"

notas.reverse() só vira a lista de cabeça para baixo: [7, 10, 8] vira [8, 10, 7], que não está em ordem nenhuma. Para a ordem decrescente, é notas.sort(reverse=True).

Quando dá errado

lista = lista.sort(): a lista vira None

O mesmo erro do append, com outro método:

compras = ["leite", "arroz", "feijão", "café"]
compras = compras.sort()
print(compras)
print(compras[0])

$ python3 sort_none.py
None
Traceback (most recent call last):
  File "/home/ana/sort_none.py", line 4, in <module>
    print(compras[0])
          ~~~~~~~^^^
TypeError: 'NoneType' object is not subscriptable

Linha por linha:

  • Linha 2: o sort() ordenou a lista e devolveu None; o = guardou esse None em compras. A lista ordenada ficou sem nome e se perdeu.
  • Linha 3: o print mostrou None.
  • Linha 4: TypeError: 'NoneType' object is not subscriptable, "o objeto NoneType não aceita colchetes". Subscriptable é "que aceita índice". O None não tem itens, então compras[0] não faz sentido.

Você pode ver o None direto:

>>> fila = ["Ana", "Bruno", "Carla"]
>>> print(fila.sort())
None

Como consertar: ou compras.sort() sozinho na linha, ou compras = sorted(compras). Nunca os dois misturados. O reverse() tem o mesmo comportamento.

Números e textos misturados 
coisas = [3, "2", 1]
coisas.sort()
print(coisas)

$ python3 mistura.py
Traceback (most recent call last):
  File "/home/ana/mistura.py", line 2, in <module>
    coisas.sort()
    ~~~~~~~~~~~^^
TypeError: '<' not supported between instances of 'str' and 'int'

"O < não funciona entre um str e um int". Para ordenar, o Python precisa perguntar "este é menor que aquele?" (com o <), e ele não sabe dizer se o texto "2" é menor que o número 3. Quase sempre, isso acontece quando alguns números vieram do input() como texto. Como consertar: converta tudo para o mesmo tipo antes (int(), aula Conversão de Tipos), ou ordene com key=int se todos forem números escritos como texto.

A ordem "errada" que não é erro

Três surpresas que não dão mensagem nenhuma, só um resultado esquisito:

  • Minúsculas depois das maiúsculas: ['Carla', 'Davi', 'ana', 'bruno']. Use key=str.lower.
  • Acentos no fim: o Álvaro depois do Eduardo. É a ordem dos códigos dos caracteres; veja a nota sobre locale na seção 3.
  • Números em texto: ['10', '100', '2', '9']. Use key=int, ou guarde os números como números.

Resumo

  • lista.sort() ordena a própria lista e devolve None; sorted(lista) devolve uma lista nova e não mexe na original.
  • reverse=True dá a ordem decrescente, nos dois.
  • key=função escolhe o critério: str.lower (ignorar maiúsculas), len (tamanho), int (números em texto). Sem parênteses depois do nome.
  • Textos são comparados pelos códigos dos caracteres: maiúsculas antes das minúsculas, e letras com acento depois de todas (o Álvaro vai para o fim).
  • reverse(), reversed() e [::-1] só invertem a ordem atual; não ordenam.
  • Nunca lista = lista.sort(). E não dá para ordenar números misturados com textos.
