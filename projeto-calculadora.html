Projeto Calculadora

O primeiro projeto do guia: uma calculadora que roda no terminal. Ela pede um número, a operação e outro número, mostra o resultado e pergunta se você quer fazer outra conta. A conta em si é a parte fácil: o Python já sabe somar. O desafio é fazer o programa não quebrar quando alguém divide por zero, escolhe uma operação que não existe ou digita "seis" no lugar de um número.

Você vai praticar
  • Ler o teclado com input() e transformar o texto em número com float().
  • Escolher a conta com if e elif e depois com match e case.
  • Recusar a divisão por zero com if e else.
  • Repetir tudo com while e sair com break.
  • Limpar o que foi digitado com strip(), lower() e replace().
  • Separar o programa em funções que devolvem valores com return.
  • Não deixar o programa quebrar com try e except.

Vamos chegar lá em quatro versões. No fim de cada uma, o programa roda; cada versão acrescenta uma coisa só:

  1. Dois números e um operador (input, float, if/elif).
  2. match e a divisão por zero.
  3. Repetir até a pessoa sair (while True e break).
  4. Funções e entrada validada (def, return, try/except).

Antes de começar

Você precisa saber criar e rodar um arquivo .py (Rodando um Programa), usar variáveis e f-strings. No seu computador, crie a pasta do projeto; o arquivo vai se chamar calculadora.py:

$ mkdir -p projetos/calculadora
$ cd projetos/calculadora

Em cada versão há também uma caixa Experimente, que roda Python de verdade aqui na página. Nas missões deste projeto, a caixa tem um campo Entrada, já preenchido com as respostas que o programa vai receber, uma por linha, como se alguém as digitasse (a missão diz quais são).

Antes da versão 1: o tropeço clássico

O jeito mais curto de pedir dois números e somar seria este:

print("=== Calculadora da Ana ===")
a = input("Primeiro número: ")
b = input("Segundo número: ")
print(f"{a} + {b} = {a + b}")

$ python3 calculadora.py
=== Calculadora da Ana ===
Primeiro número: 10
Segundo número: 5
10 + 5 = 105

10 + 5 = 105? Não deu erro nenhum, mas a conta está errada. O motivo: o input() sempre devolve um texto (uma str), mesmo que a pessoa tenha digitado só algarismos. Para o Python, a vale "10" e b vale "5", e o + entre dois textos junta os textos (veja Juntar e Repetir Textos): "10" + "5" é "105". Para fazer conta, é preciso converter o texto em número antes. É o primeiro passo da versão 1.

Versão 1 · Dois números e um operador

A calculadora pede o primeiro número, a operação e o segundo número. Os números passam pelo float(), que transforma o texto num número com casas decimais (um float, veja Números), porque a Ana quer fazer contas como 7.5 / 2. A operação fica como texto mesmo: "+", "-", "*" ou "/". Para escolher a conta, uma escada de if e elif.

print("=== Calculadora da Ana ===")

elif op == "*":

elif op == "/":

else:
    print(f"Operação desconhecida: {op}")

Por que float e não int?

O int() converte para número inteiro, e recusa "7.5" (dá erro). Com float(), a calculadora aceita as duas coisas: "10" vira 10.0 e "7.5" vira 7.5. Mais em Conversão de Tipos.

0.1 + 0.2 não dá exatamente 0.3 
$ python3 calculadora.py
=== Calculadora da Ana ===
Primeiro número: 0.1
Operação (+ - * /): +
Segundo número: 0.2
0.1 + 0.2 = 0.30000000000000004

Não é defeito da calculadora nem do Python: o computador guarda os números com casas decimais em binário, e alguns, como 0.1, não têm representação exata (como 1/3 não tem em decimal: 0,3333…). Sobra um erro minúsculo na 17ª casa. Quase toda linguagem de programação dá o mesmo resultado. A aula Números explica; na versão 4, a calculadora arredonda o resultado na hora de mostrar.

Versão 2 · match e a divisão por zero

Duas mudanças. A primeira é só de forma: a escada de if/elif que compara a mesma variável com vários valores fica mais fácil de ler com match e case ("combinar" e "caso"). A segunda conserta um defeito: antes de dividir, a calculadora confere se o segundo número é zero.

print("=== Calculadora da Ana ===")
a = float(input("Primeiro número: "))
op = input("Operação (+ - * /): ")
b = float(input("Segundo número: "))

match op:
    case "+":
        print(f"{a} + {b} = {a + b}")
    case "-":
        print(f"{a} - {b} = {a - b}")
    case "*":
        print(f"{a} * {b} = {a * b}")
    case "/":
        if b == 0:
            print("Não dá para dividir por zero.")
        else:
            print(f"{a} / {b} = {a / b}")
    case _:
        print(f"Operação desconhecida: {op}")
match op:
"Compare o valor de op com os casos abaixo." O match existe desde o Python 3.10.
case "+":
Se op for "+", faz o bloco de baixo (indentado com mais 4 espaços) e pula todos os outros casos.
if b == 0:
Dentro do caso da divisão, um if comum: se o divisor for zero, avisa em vez de dividir. Um bloco pode ter qualquer coisa dentro, inclusive outro if (veja Condições Aninhadas).
case _:
O sublinhado é o "qualquer outra coisa": combina com tudo, por isso fica por último. Faz o papel do else.

Em vez do traceback da versão 1, uma frase que a Ana entende. Isso é prevenir o erro: o programa confere antes de fazer a conta perigosa. (A outra estratégia, tratar o erro depois que ele acontece, com try/except, aparece na versão 4.)

Comparar com 0 funciona com 0.0

Depois do float(), o b vale 0.0, e não 0. Mesmo assim, b == 0 dá True: o Python compara o valor dos números, não o tipo. 0.0 == 0 é verdadeiro.

Esquecer o case _

Se o case _: sair do programa e a Ana digitar x, nenhum caso combina e o match simplesmente não faz nada: o programa termina sem mostrar resultado nem aviso. Não é um erro para o Python (por isso não há traceback), mas para quem usa parece que a calculadora "travou calada". Sempre que os casos não cobrirem tudo, ponha um case _ no fim.

Versão 3 · Repetir até a pessoa sair

Até agora, cada conta exige rodar o programa de novo. A Ana quer fazer várias contas seguidas. A solução é colocar tudo dentro de um laço while ("enquanto") e, no fim de cada volta, perguntar se ela quer continuar.

print("=== Calculadora da Ana ===")

while True:
    a = float(input("Primeiro número: "))
    op = input("Operação (+ - * /): ")
    b = float(input("Segundo número: "))

    match op:
        case "+":
            print(f"{a} + {b} = {a + b}")
        case "-":
            print(f"{a} - {b} = {a - b}")
        case "*":
            print(f"{a} * {b} = {a * b}")
        case "/":
            if b == 0:
                print("Não dá para dividir por zero.")
            else:
                print(f"{a} / {b} = {a / b}")
        case _:
            print(f"Operação desconhecida: {op}")

    continuar = input("Outra conta? (s/n): ").strip().lower()
    if continuar != "s":
        break

print("Até logo!")
while True:
"Enquanto verdadeiro": um laço que, sozinho, nunca termina. Tudo o que está indentado embaixo dele se repete. Quem decide a hora de parar é o break lá dentro.

As perguntas e o match agora estão dentro do while, por isso ganharam mais um nível de indentação. É a indentação que diz ao Python o que faz parte do laço (veja Sintaxe e Indentação).

Três passos em fila: pergunta, tira os espaços das pontas (strip, "aparar") e passa para minúsculas (lower, "mais baixo"). Assim, S, s e " s " viram todos "s". Veja Métodos de Texto.

Por que while True com break?

Dava para escrever while continuar == "s":, mas aí a variável continuar teria de existir antes do laço (com um continuar = "s" só para entrar na primeira volta). O while True com break no fim deixa a ordem natural: primeiro faz a conta, depois pergunta. É um padrão muito comum em programas que conversam com a pessoa.

Versão 4 · Funções e entrada validada

A versão 3 já faz várias contas, mas ainda quebra com seis, com 2,5 e com qualquer coisa que não seja número. E o programa ficou comprido: está tudo misturado num bloco só. A versão 4 resolve as duas coisas de uma vez: cada tarefa vira uma função com nome, e a função que lê números insiste até receber um número de verdade.

OPERACOES = "+-*/"


def ler_numero(pergunta):
    """Pergunta até a pessoa digitar um número; aceita vírgula ou ponto."""
    while True:
        texto = input(pergunta).strip()
        try:
            return float(texto.replace(",", "."))
        except ValueError:
            print(f'"{texto}" não é um número. Tente de novo.')


def ler_operacao():
    """Pergunta até a pessoa digitar uma das quatro operações."""
    while True:
        op = input("Operação (+ - * /): ").strip()
        if len(op) == 1 and op in OPERACOES:
            return op
        print(f"Operação desconhecida: {op}")


def formatar(numero):
    """Mostra 15 em vez de 15.0, com no máximo 6 casas decimais."""
    numero = round(numero, 6)
    if numero.is_integer():
        return str(int(numero))
    return str(numero)


def calcular(a, op, b):
    """Faz a conta e devolve o resultado (ou None, se for dividir por zero)."""
    match op:
        case "+":
            return a + b
        case "-":
            return a - b
        case "*":
            return a * b
        case "/":
            if b == 0:
                return None
            return a / b


print("=== Calculadora da Ana ===")

while True:
    a = ler_numero("Primeiro número: ")
    op = ler_operacao()
    b = ler_numero("Segundo número: ")

    resultado = calcular(a, op, b)
    if resultado is None:
        print("Não dá para dividir por zero.")
    else:
        print(f"{formatar(a)} {op} {formatar(b)} = {formatar(resultado)}")

    continuar = input("Outra conta? (s/n): ").strip().lower()
    if continuar != "s":
        break

print("Até logo!")

Parece muito código novo, mas o "programa principal" (do print do título até o fim) ficou mais curto e mais fácil de ler do que na versão 3: ele só chama funções com nomes que dizem o que fazem. Vamos às peças.

Usar a função antes de criá-la: NameError

Se o programa principal ficar em cima das funções (o while primeiro, os def depois), acontece isto:

$ python3 calculadora.py
=== Calculadora da Ana ===
Traceback (most recent call last):
  File "/home/ana/projetos/calculadora/calculadora.py", line 4, in <module>
    a = ler_numero("Primeiro número: ")
        ^^^^^^^^^^
NameError: name 'ler_numero' is not defined

NameError: name 'ler_numero' is not defined = "o nome ler_numero não está definido". O Python lê e executa o arquivo de cima para baixo. O def é uma instrução como outra qualquer: só depois que ela roda a função passa a existir. Quando a linha 4 chamou ler_numero, o def ainda estava lá embaixo, sem ter rodado. Como consertar: as funções primeiro, o programa principal no fim, como na versão 4.

Missão (versão 4): a função ler_numero ainda não se protege: com a entrada da missão (abc, 10, +, 5, n), o abc derruba o programa com ValueError. Coloque o return float(…) dentro de um try: e, no except ValueError:, mostre "abc" não é um número. Tente de novo. (com o texto que a pessoa digitou). O while True que já existe faz a pergunta de novo.

Formas diferentes de escolher a conta

A calculadora usou if/elif e depois match. Há um terceiro jeito, que você vai encontrar em programas prontos: um dicionário que liga cada símbolo a uma função. O módulo operator (da biblioteca do Python) já traz as funções das contas: operator.add soma, operator.mul multiplica, e assim por diante.

import operator

a, op, b = 10.0, "*", 3.0

# Forma 1: if/elif
if op == "+":
    print("if/elif:", a + b)
elif op == "*":
    print("if/elif:", a * b)

# Forma 2: match/case
match op:
    case "+":
        print("match:", a + b)
    case "*":
        print("match:", a * b)

# Forma 3: um dicionário de funções
contas = {
    "+": operator.add,
    "-": operator.sub,
    "*": operator.mul,
    "/": operator.truediv,
}
print("dicionário:", contas[op](a, b))

$ python3 formas.py
if/elif: 30.0
match: 30.0
dicionário: 30.0

Na forma 3, contas[op] busca no dicionário a função ligada a "*" (a operator.mul), e o (a, b) logo depois a chama com os dois números.

FormaQuando usar
if / elifPoucas opções, ou condições diferentes entre si (op == "/" and b == 0). Funciona em qualquer versão do Python.
match / caseComparar uma variável com vários valores fixos. Fica limpo de ler. Precisa do Python 3.10 ou mais novo.
Dicionário de funçõesMuitas opções que fazem coisas do mesmo formato. Acrescentar uma operação é acrescentar uma linha no dicionário. Exige já conhecer dicionários e funções.
E o eval()?

Na internet você vai achar calculadoras de uma linha só: print(eval(input())). O eval() ("avaliar") executa um texto como se fosse código Python:

$ python3
Python 3.14.4 (main, Aug 20 2026, 10:41:58) [GCC 15.2.0] on linux
Type "help", "copyright", "credits" or "license" for more information.

>>> eval("2,5")

Parece prático, mas repare no segundo: 2,5 não deu erro nem 2.5; virou um par de números (uma tupla). E o pior: o eval() executa qualquer código que a pessoa digitar, inclusive um que apague arquivos. Nunca use eval() em algo que veio do teclado, de um arquivo ou da internet. A calculadora da Ana é mais longa, mas ela sabe exatamente o que aceita.

Desafio no editor: acrescente % e ** à calculadora. Resumo

  • O input() sempre devolve texto. Para fazer conta, converta com float() (ou int()); sem isso, "10" + "5" dá "105".
  • if/elif e match/case escolhem a conta; o case _ pega o que sobrou.
  • A divisão por zero dá ZeroDivisionError: previna com if b == 0.
  • while True com break repete até a pessoa pedir para sair; .strip().lower() deixa a resposta tolerante.
  • Texto que não é número dá ValueError: trate com try/except dentro de um laço que pergunta de novo.
  • Funções com nomes claros deixam o programa principal curto. Elas precisam ser criadas (def) antes de serem chamadas.
  • Nunca use eval() no que a pessoa digita.
