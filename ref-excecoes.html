Python Exceções Embutidas

Quando algo dá errado, o Python para o programa e mostra o nome de uma exceção (exception, "exceção": um erro que acontece com o programa já rodando), como ValueError ou KeyError, seguido de uma mensagem. Esta página é o dicionário desses nomes: a árvore de famílias, a mensagem real que cada uma mostra no Python 3.14 e quando ela acontece. Para aprender a ler a mensagem inteira, veja a aula Lendo uma Mensagem de Erro; para tratar o erro, try e except.

Como ler as tabelas
  • Exemplo é um código curto que provoca o erro; Mensagem real é a última linha do traceback que o Python 3.14.4 mostrou no computador da Ana. As mensagens do Python são sempre em inglês; a coluna "Quando acontece" traduz a ideia.
  • A última linha tem sempre o formato NomeDaExceção: explicação. Algumas exceções não têm explicação, e a linha é só o nome (por exemplo, StopIteration).
  • A coluna Aula leva à aula em que o erro aparece pela primeira vez.

A árvore de exceções

As exceções são classes organizadas em famílias, como uma árvore genealógica. Cada uma "é filha" de outra mais geral. Isso importa por um motivo prático: um except pega a exceção que você escreveu e todas as filhas dela. except LookupError pega IndexError e KeyError; except OSError pega todos os erros de arquivo.

Por que nunca usar except BaseException (nem except: sozinho)

Repare na última linha: KeyboardInterrupt não é filha de Exception. Ela, SystemExit e GeneratorExit ficam de fora de propósito: não são "erros", são pedidos para o programa parar (o Ctrl-C do teclado, o sys.exit()). Um except Exception deixa esses pedidos passarem; um except BaseException ou um except: sem nome os engole, e o programa não para nem com Ctrl-C. Quando precisar de um "pega tudo", o mais largo aceitável é except Exception, e de preferência com o nome exato do erro que você espera.

A família ajuda a tratar vários erros parecidos de uma vez. O estoque da Ana tem um dicionário e uma lista; procurar algo que não existe dá KeyError num e IndexError na outra, e um único except LookupError pega os dois:

estoque = {"pão": 30, "leite": 12}
prateleira = ["pão", "leite"]

for tentativa in ["café", 5]:
    try:
        if isinstance(tentativa, str):
            print(estoque[tentativa])
        else:
            print(prateleira[tentativa])
    except LookupError as erro:
        print(f"{type(erro).__name__}: {erro}")

$ python3 estoque.py
KeyError: 'café'
IndexError: list index out of range

TypeError ou ValueError?

TypeError = o tipo está errado (deu um número onde se esperava um texto). ValueError = o tipo está certo, mas o valor não serve (é um texto, mas "dez" não vira número). Em int("dez") o int aceita textos, só não esse.

Novidade do 3.14: except com vírgula, sem parênteses 3.14

Até o 3.13, vários erros no mesmo except precisavam de parênteses: except (ValueError, TypeError):. No 3.14 os parênteses podem ficar de fora (PEP 758): except ValueError, TypeError: rodou no computador da Ana e pegou o ValueError. Se o seu programa também vai rodar num Python mais antigo (o Debian 13 traz o 3.13), continue usando os parênteses, que valem em todas as versões. Com as erro, os parênteses continuam obrigatórios: sem eles, o 3.14 recusa o arquivo com SyntaxError: multiple exception types must be parenthesized when using 'as'.

Livre: cada linha da lista é um código que dá erro. O programa roda um por um e mostra a família de cada erro, da filha até a mãe. Acrescente os seus (por exemplo "[].pop()" ou "float('1,5')") e veja de que família eles são.

O except com o nome errado

A Ana quis tratar o caso de alguém digitar a idade por extenso, mas pôs o nome errado no except:

texto = "dez"
try:
    idade = int(texto)
    print("Daqui a 1 ano:", idade + 1)
except ZeroDivisionError:
    print("Não é um número:", texto)

$ python3 idade.py
Traceback (most recent call last):
  File "/home/ana/idade.py", line 3, in <module>
    idade = int(texto)
ValueError: invalid literal for int() with base 10: 'dez'

O except ZeroDivisionError só pega divisão por zero. O erro foi outro, ValueError, que não é filho de ZeroDivisionError: o except o deixou passar e o programa parou. A última linha do traceback diz qual nome usar.

Missão: conserte o programa da Ana: troque o nome no except pela exceção que o int("dez") realmente lança (leia a última linha do erro ao rodar). A saída deve ser Não é um número: dez.

texto = "dez"
try:
    idade = int(texto)
    print("Daqui a 1 ano:", idade + 1)
except ZeroDivisionError:
    print("Não é um número:", texto)

texto = "dez"
try:
    idade = int(texto)
    print("Daqui a 1 ano:", idade + 1)
except ValueError:
    print("Não é um número:", texto)

Resumo

  • O nome da exceção está no começo da última linha do traceback: NomeDaExceção: explicação.
  • As exceções formam uma árvore. except Mãe pega a mãe e todas as filhas: LookupError pega IndexError e KeyError; OSError pega os erros de arquivo; ArithmeticError pega ZeroDivisionError.
  • KeyboardInterrupt e SystemExit ficam fora de Exception: por isso o "pega tudo" certo é except Exception, nunca except: sozinho.
  • TypeError = tipo errado; ValueError = tipo certo, valor ruim.
  • SyntaxError e IndentationError aparecem antes de o programa rodar; um try no mesmo arquivo não os pega.
  • Avisos (Warning) não param o programa.
