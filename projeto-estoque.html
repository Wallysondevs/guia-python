Projeto Estoque com SQLite

A padaria da Ana controla o estoque num caderno: chegou café, risca e escreve o número novo; vendeu bolo, risca de novo. Neste projeto, o caderno vira um programa. Os produtos ficam guardados num banco de dados SQLite, um arquivo estoque.db que continua lá depois que o programa termina, e um menu no terminal permite listar, cadastrar, dar entrada, dar saída e ver um relatório. O programa recusa um produto repetido, não deixa o estoque ficar negativo e não quebra quando alguém digita "quinze" no lugar de 15.

Você vai praticar
  • Abrir um banco, criar a tabela e gravar com o módulo sqlite3: CREATE TABLE, INSERT, SELECT, UPDATE, DELETE, sempre com o marcador ?.
  • Confirmar as mudanças com with con: (o commit automático).
  • Separar o programa em funções com parâmetros e return.
  • Percorrer o resultado com for e desempacotamento, e alinhar colunas com f-strings.
  • Tratar erros com try e except (IntegrityError, ValueError).
  • Fazer o menu com while, break e match e case.

Vamos chegar lá em quatro versões. No fim de cada uma o programa roda, e cada versão acrescenta uma coisa só:

  1. O banco, a tabela e a listagem (connect, CREATE TABLE, INSERT, SELECT).
  2. Funções e o cadastro sem repetição (def, with con:, IntegrityError).
  3. Entrada e saída de mercadoria (UPDATE, sem deixar negativo).
  4. O menu e o relatório (while, match, sum(), entrada validada).

Antes de começar

Leia antes a aula Python com Banco de Dados (sqlite3): ela explica cada comando SQL usado aqui, com calma. Você também precisa saber criar e rodar um arquivo .py (Rodando um Programa). No seu computador, crie a pasta do projeto; o arquivo vai se chamar estoque.py:

$ mkdir -p projetos/estoque
$ cd projetos/estoque
No editor do guia, cada Rodar começa do zero

Nas caixas Experimente desta página, o programa cria o estoque.db e o usa de verdade, mas, como em toda caixa do guia, cada Rodar parte do zero: os arquivos da execução anterior somem. Por isso o programa cria o banco e a tabela sozinho, e coloca os produtos iniciais quando a tabela está vazia. No seu computador, o arquivo fica na pasta e os dados se acumulam de uma execução para outra, como nas sessões de terminal desta página.

Versão 1 · O banco, a tabela e a listagem

A primeira versão abre (ou cria) o banco, cria a tabela de produtos se ela ainda não existir, coloca quatro produtos se a tabela estiver vazia e mostra o estoque em colunas.

import sqlite3

con = sqlite3.connect("estoque.db")
con.execute("""
    CREATE TABLE IF NOT EXISTS produtos (
        id INTEGER PRIMARY KEY,
        nome TEXT NOT NULL UNIQUE,
        quantidade INTEGER NOT NULL,
        preco REAL NOT NULL
    )
""")

iniciais = [
    ("Pão francês", 120, 0.80),
    ("Leite integral 1 L", 24, 5.50),
    ("Café 500 g", 10, 18.90),
    ("Bolo de milho", 4, 18.00),
]

quantos = con.execute("SELECT count(*) FROM produtos").fetchone()[0]
if quantos == 0:
    con.executemany(
        "INSERT INTO produtos (nome, quantidade, preco) VALUES (?, ?, ?)",
        iniciais,
    )
    con.commit()
    print(f"Banco novo: {len(iniciais)} produtos cadastrados.")

print("=== Estoque da Padaria Pão Quente ===")
for nome, quantidade, preco in con.execute(
    "SELECT nome, quantidade, preco FROM produtos ORDER BY nome"
):
    print(f"{nome:<20} {quantidade:>4} un.   R$ {preco:>6.2f}")

con.close()

Por partes

sqlite3.connect("estoque.db")
Abre o banco guardado no arquivo estoque.db. Se o arquivo não existe, ele é criado, vazio.
CREATE TABLE IF NOT EXISTS produtos (…)
Cria a tabela só se ela ainda não existir. Sem o IF NOT EXISTS, a segunda execução daria erro (table produtos already exists). O texto entre três aspas (""") pode ocupar várias linhas.
id INTEGER PRIMARY KEY
Um número único para cada produto, que o SQLite preenche sozinho: 1, 2, 3…
nome TEXT NOT NULL UNIQUE
O nome é um texto obrigatório (NOT NULL) e não pode se repetir (UNIQUE). Essa regra vai trabalhar a nosso favor na versão 2.
quantidade INTEGER, preco REAL
Um número inteiro e um número com casas decimais.
fetchone()[0]
O SELECT count(*) devolve uma linha com um valor só, a contagem. fetchone() pega essa linha (uma tupla) e [0] pega o valor de dentro.
executemany(…, iniciais)
Roda o mesmo INSERT uma vez para cada tupla da lista. Cada ? é preenchido por um item da tupla, na ordem: nome, quantidade, preço.
con.commit()
Grava de verdade no arquivo. Sem ele, os produtos sumiriam ao fechar o banco.
for nome, quantidade, preco in con.execute(…)
Percorre o resultado do SELECT: cada linha é uma tupla, aberta em três variáveis.
{nome:<20} {quantidade:>4} {preco:>6.2f}
Alinhamento: o nome à esquerda em 20 posições, a quantidade à direita em 4, o preço à direita em 6 com 2 casas (Formatação). É o que deixa as colunas retas.

Versão 2 · Funções e o cadastro sem repetição

O programa vai crescer, então é hora de separá-lo em funções, cada uma com uma tarefa: abrir_banco, cadastrar e listar. E o cadastro precisa lidar com o caso em que o produto já existe.

import sqlite3

INICIAIS = [
    ("Pão francês", 120, 0.80),
    ("Leite integral 1 L", 24, 5.50),
    ("Café 500 g", 10, 18.90),
    ("Bolo de milho", 4, 18.00),
]


def abrir_banco(arquivo):
    con = sqlite3.connect(arquivo)
    con.execute("""
        CREATE TABLE IF NOT EXISTS produtos (
            id INTEGER PRIMARY KEY,
            nome TEXT NOT NULL UNIQUE,
            quantidade INTEGER NOT NULL,
            preco REAL NOT NULL
        )
    """)
    quantos = con.execute("SELECT count(*) FROM produtos").fetchone()[0]
    if quantos == 0:
        with con:
            con.executemany(
                "INSERT INTO produtos (nome, quantidade, preco) VALUES (?, ?, ?)",
                INICIAIS,
            )
    return con


def cadastrar(con, nome, quantidade, preco):
    try:
        with con:
            con.execute(
                "INSERT INTO produtos (nome, quantidade, preco) VALUES (?, ?, ?)",
                (nome, quantidade, preco),
            )
    except sqlite3.IntegrityError:
        print(f"Já existe um produto chamado {nome}.")
        return False
    print(f"Cadastrado: {nome}")
    return True


def listar(con):
    print("=== Estoque da Padaria Pão Quente ===")
    for nome, quantidade, preco in con.execute(
        "SELECT nome, quantidade, preco FROM produtos ORDER BY nome"
    ):
        print(f"{nome:<20} {quantidade:>4} un.   R$ {preco:>6.2f}")


con = abrir_banco("estoque.db")
cadastrar(con, "Sonho", 15, 6.50)
cadastrar(con, "Café 500 g", 5, 19.90)
listar(con)
con.close()
INICIAIS
A lista saiu do meio do programa e foi para o topo. O nome em MAIÚSCULAS é o costume para valores fixos, que o programa só lê (aula Escopo).
def abrir_banco(arquivo): … return con
Tudo o que a versão 1 fazia para preparar o banco, agora numa função que devolve a conexão pronta.
with con:
Um bloco que faz o commit sozinho quando termina bem e desfaz tudo (rollback) se der erro no meio. É mais seguro que lembrar de chamar con.commit() (aula sqlite3).
try: … except sqlite3.IntegrityError:
Se o nome já existe, a regra UNIQUE da tabela recusa o INSERT com um IntegrityError ("erro de integridade"). O except pega esse erro e mostra um aviso, em vez de o programa quebrar.
return False / return True
A função conta a quem chamou se cadastrou ou não. Este programa ainda não usa a resposta, mas ela já está lá para quem precisar.

Leia de baixo para cima: sqlite3.IntegrityError: UNIQUE constraint failed: produtos.nome, "a regra UNIQUE falhou na coluna nome da tabela produtos". O caminho mostra que a linha 51 (o programa principal) chamou cadastrar, e dentro dele o con.execute da linha 33 foi recusado. Como o execute ocupa várias linhas, o Python marca o comando inteiro com ^. Repare que o banco não aceitou o café repetido mesmo sem o try: quem protege os dados é a regra UNIQUE da tabela. O try só faz o programa reagir com educação, em vez de quebrar.

Versão 3 · Entrada e saída de mercadoria

Chegou café, vendeu pão: a quantidade muda. Uma função só, movimentar, faz as duas coisas: um número positivo é entrada, um negativo é saída. Antes de gravar, ela confere duas coisas: se o produto existe e se a saída não deixa o estoque negativo. O resto do programa (abrir_banco, cadastrar, listar) é igual ao da versão 2; estas são as partes novas:

def movimentar(con, nome, quantidade):
    linha = con.execute(
        "SELECT quantidade FROM produtos WHERE nome = ?", (nome,)
    ).fetchone()
    if linha is None:
        print(f"Produto não encontrado: {nome}")
        return False
    atual = linha[0]
    nova = atual + quantidade
    if nova < 0:
        print(f"Não dá para tirar {-quantidade} de {nome}: só há {atual}.")
        return False
    with con:
        con.execute(
            "UPDATE produtos SET quantidade = ? WHERE nome = ?", (nova, nome)
        )
    print(f"{nome}: {atual} -> {nova}")
    return True


con = abrir_banco("estoque.db")
movimentar(con, "Pão francês", -30)
movimentar(con, "Café 500 g", 12)
movimentar(con, "Bolo de milho", -6)
movimentar(con, "Pão de mel", 5)
listar(con)
con.close()
WHERE nome = ?", (nome,)
Procura a linha do produto. Repare na vírgula em (nome,): é ela que faz uma tupla de um item só (aula Tuplas). Sem a vírgula, dá erro; veja abaixo.
if linha is None:
Quando o SELECT não acha nada, o fetchone() devolve None (aula O Valor None): o produto não existe.
nova = atual + quantidade
Com -30, 120 + (-30) dá 90. A mesma conta serve para entrada e saída.
if nova < 0:
A saída deixaria o estoque negativo: avisa e sai da função com return False, sem gravar nada. O {-quantidade} mostra o número sem o sinal de menos.
UPDATE produtos SET quantidade = ? WHERE nome = ?
Troca a quantidade daquele produto. São dois ?, então a tupla tem dois valores, na mesma ordem: (nova, nome). Sem o WHERE, o UPDATE mudaria todos os produtos.

As partes novas, uma por uma

MINIMO = 5
Abaixo de quantas unidades um produto aparece como "acabando". Fica no topo, com nome, para ser fácil de mudar.
SELECT sum(quantidade * preco)
O próprio banco multiplica a quantidade pelo preço de cada produto e soma tudo: o valor do que está na prateleira.
WHERE quantidade < ? … (MINIMO,)
Os produtos abaixo do mínimo, do que tem menos para o que tem mais (ORDER BY quantidade). O fetchall() devolve uma lista de tuplas; lista vazia conta como falso no if acabando: (aula Booleanos).
ler_inteiro e ler_preco
Perguntam até receber um número válido: o while True repete, e o return dentro do try sai da função assim que a conversão dá certo. O ler_preco troca a vírgula por ponto, para aceitar 6,50. É a mesma técnica da versão 4 do Projeto Calculadora.
-ler_inteiro("Quantas saíram? ")
Na saída, o número digitado vira negativo antes de ir para o movimentar: a Ana digita 3, a função recebe -3.
match opcao: / case "1": … case _:
Escolhe o que fazer pela opção digitada (um texto). O case _ pega qualquer outra coisa (aula match e case).
case "0": … break
Sai do while True; depois dele, o programa fecha o banco e termina.

A sessão completa está no começo da página, em O que vamos construir. O valor do relatório confere: 1 × 18,00 + 22 × 18,90 + 24 × 5,50 + 120 × 0,80 + 15 × 6,50 = R$ 759,30.

Formas diferentes de confirmar as mudanças

O projeto usou con.commit() na versão 1 e with con: a partir da versão 2. As duas gravam; a diferença está no que acontece quando dá erro no meio.

FormaQuando usar
con.execute(…) + con.commit()Funciona, mas depende de você lembrar do commit em todo lugar que muda dados. Um esquecimento e a mudança some, sem aviso
with con: + con.execute(…)O preferido: grava sozinho no fim do bloco e, se algo der errado no meio, desfaz tudo do bloco
executemany(…, lista)Para gravar várias linhas com o mesmo comando, como os produtos iniciais

def abrir_banco(arquivo):
    con = sqlite3.connect(arquivo)
    con.execute("""
        CREATE TABLE IF NOT EXISTS produtos (
            id INTEGER PRIMARY KEY,
            nome TEXT NOT NULL UNIQUE,
            quantidade INTEGER NOT NULL,
            preco REAL NOT NULL
        )
    """)
    quantos = con.execute("SELECT count(*) FROM produtos").fetchone()[0]
    if quantos == 0:
        with con:
            con.executemany(
                "INSERT INTO produtos (nome, quantidade, preco) VALUES (?, ?, ?)",
                INICIAIS,
            )
    return con


def cadastrar(con, nome, quantidade, preco):
    try:
        with con:
            con.execute(
                "INSERT INTO produtos (nome, quantidade, preco) VALUES (?, ?, ?)",
                (nome, quantidade, preco),
            )
    except sqlite3.IntegrityError:
        print(f"Já existe um produto chamado {nome}.")
        return False
    print(f"Cadastrado: {nome}")
    return True

    print("=== Estoque da Padaria Pão Quente ===")

def movimentar(con, nome, quantidade):
    linha = con.execute(
        "SELECT quantidade FROM produtos WHERE nome = ?", (nome,)
    ).fetchone()
    if linha is None:
        print(f"Produto não encontrado: {nome}")

    return True

Resumo

  • O banco SQLite é um arquivo (estoque.db): os dados continuam lá depois que o programa termina. No editor do guia, cada Rodar começa sem ele; por isso o programa cria a tabela e os produtos iniciais sozinho.
  • CREATE TABLE IF NOT EXISTS e "só cadastra os iniciais se a tabela está vazia" deixam o programa rodar quantas vezes for preciso.
  • Todo valor que vem de variável entra no SQL por um ?, com uma tupla na mesma ordem; com um valor só, (nome,).
  • Toda mudança vai dentro de with con:: grava no fim, desfaz se der erro. Sem isso, a mudança some sem aviso.
  • A regra UNIQUE protege os dados; o try/except sqlite3.IntegrityError faz o programa reagir com educação.
  • O banco guarda o que você mandar: conferir se a saída deixa o estoque negativo é trabalho do programa.
  • Funções pequenas, cada uma com uma tarefa (abrir_banco, cadastrar, movimentar, relatorio), deixam o menu curto e fácil de ler.
