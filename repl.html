Python O Modo Interativo (>>>)

Até aqui você escreveu o programa num arquivo e mandou o Python rodar tudo de uma vez. Existe outro jeito de usar o Python: conversar com ele, uma linha de cada vez. Você digita uma instrução, aperta Enter, e ele responde na hora. É o modo interativo, também chamado de REPL, e você o reconhece pelo prompt >>>. Ele é perfeito para testar uma ideia, fazer uma conta ou tirar uma dúvida rápida sobre como algo funciona. Nesta aula você vai abrir, usar e fechar o modo interativo do Python 3.14, que ficou bem mais confortável nas versões recentes.

Você vai aprender
  • A abrir o modo interativo com python3, e o que diz a mensagem de boas-vindas.
  • A diferença entre o $ (o terminal) e o >>> (o Python).
  • Por que, no >>>, o resultado aparece sozinho, sem print, e num arquivo não.
  • A escrever blocos de várias linhas (o prompt ...) e a terminá-los.
  • A sair: exit, quit, Ctrl+D.
  • Os atalhos: histórico com as setas, Tab, help, F1, F2, F3, e as cores do Python 3.14.
  • O que acontece quando dá erro no >>>, e o que se perde quando você sai.

A ideia: a calculadora e a carta

Existem dois jeitos de pedir uma coisa a alguém. Você pode escrever uma carta com todos os pedidos, em ordem, e entregar: a pessoa lê tudo e faz. Ou pode conversar: pede uma coisa, espera a resposta, e decide o próximo pedido conforme o que ouviu.

Programa em arquivo (python3 ola.py)Modo interativo (>>>)
ComparaçãoA carta: tudo escrito antes, executado de uma vezA conversa (ou uma calculadora): uma linha, uma resposta
Fica guardado?Sim: o arquivo continua lá para rodar de novoNão: ao sair, o que você digitou não vira arquivo
Mostra resultadosSó o que você mandar com printO valor de cada linha aparece sozinho
Bom paraProgramas de verdade, que você vai usar de novoTestar uma ideia, fazer contas, tirar dúvidas

"REPL" é a sigla em inglês do que ele faz, sem parar: Read (lê o que você digitou), Eval (avalia, ou seja, executa), Print (mostra o resultado) e Loop (volta ao começo e espera a próxima linha).

Com python3 -q (de quiet, "quieto"), ele abre direto no >>>, sem a mensagem de boas-vindas. Várias sessões desta aula usam o -q para economizar espaço.

$ ou >>>: quem está ouvindo?

Repare no começo da linha antes de digitar. Com $ (no guia, ana@notebook:~$), quem ouve é o terminal: ali vão ls, cd, python3 ola.py. Com >>>, quem ouve é o Python: ali vão print("Olá"), 2 + 3. Trocar um pelo outro é o erro mais comum de quem está começando; a seção Quando dá errado mostra as mensagens dos dois lados.

2. A calculadora que responde sozinha

Digite uma conta e aperte Enter:

>>> 2 + 3
5
>>> 10 / 4
2.5
>>> 7 * 8 - 6
50

O Python calculou e mostrou o resultado, sem você pedir. O * é a multiplicação e o / é a divisão; o resultado 2.5 usa ponto como separador decimal, como em inglês. (As contas têm aula própria: Operadores Aritméticos.)

Com e sem print

No modo interativo, o Python mostra o valor de cada linha que você digita. Olhe a diferença entre escrever um texto sozinho e mandar o print mostrá-lo:

>>> "Ana"
'Ana'                                              « o valor: um texto (por isso as aspas)
>>> print("Ana")
Ana                                                « o print mostra o texto, sem aspas

Na primeira linha, o Python está dizendo "o valor do que você digitou é o texto 'Ana'", e as aspas mostram que é um texto. Na segunda, o print escreve o texto na tela, como o leitor do seu programa veria, sem aspas. Mais um exemplo, com uma variável (um nome que guarda um valor):

>>> nome = "Ana"                                « guardar não mostra nada
>>> nome
'Ana'
>>> print("Olá,", nome)
Olá, Ana

A linha nome = "Ana" não mostrou nada: ela só guarda o valor, e guardar não tem resultado para mostrar. Digitar nome sozinho mostra o que está guardado.

Num arquivo, sem print, nada aparece

Essa "resposta sozinha" é só do modo interativo. Num programa em arquivo, o Python calcula tudo, mas só mostra o que você mandar mostrar. A Ana gravou as mesmas linhas num arquivo:

2 + 3
"Ana"

$ python3 conta.py
$                                                  « nenhuma saída

Nada. O Python fez a conta, viu o texto e terminou, sem mostrar coisa nenhuma, porque ninguém pediu. As caixas Experimente do guia rodam um arquivo (o main.py), então lá vale a mesma regra: use print.

Missão: o editor roda um arquivo, como python3 main.py, então a conta abaixo não aparece. Rode para ver que não sai nada. Depois, ponha a conta dentro de um print( ) e rode de novo, até aparecer o 5.

2 + 3

print(2 + 3)

O _: o último resultado

No modo interativo, o sublinhado _ guarda o último valor que o Python mostrou sozinho. É útil para continuar uma conta:

>>> 2 + 3
5
>>> _ * 10                                       « o 5 de antes, vezes 10
50

O _ só existe no modo interativo, e só guarda os valores que apareceram sozinhos (o que o print escreveu não conta). Num arquivo, use variáveis com nomes de verdade.

3. Várias linhas: o prompt ...

Algumas instruções do Python ocupam mais de uma linha, como o for, que repete um bloco. Quando a linha termina com dois-pontos (:), o Python sabe que vem um bloco e troca o prompt para ..., que quer dizer "continue, estou esperando o resto":

$ python3 -q
>>> compras = ["arroz", "feijão", "café"]
>>> for item in compras:
...     print("Comprar:", item)                    « os 4 espaços vieram sozinhos
...                                                « linha vazia: fim do bloco
Comprar: arroz
Comprar: feijão
Comprar: café
>>> len(compras)
3
  1. Depois de for item in compras: e Enter, o prompt virou ... e o cursor já começou com 4 espaços de recuo. O modo interativo do Python 3.13 em diante indenta sozinho depois dos dois-pontos. (A indentação é o assunto da aula Sintaxe e Indentação.)
  2. A Ana digitou o print e apertou Enter. O Python continuou esperando, porque o bloco poderia ter mais linhas.
  3. Para dizer "acabou o bloco", ela apertou Enter numa linha vazia. Só então o Python executou o for inteiro.

Os parênteses também fazem o Python esperar. Se você esquecer de fechar um, ele mostra ... até você fechar:

>>> print("Olá, Ana!"
... )                                              « o parêntese que faltava
Olá, Ana!
A indentação automática e a linha vazia

Como o recuo vem sozinho, a próxima linha que você digitar também fica dentro do bloco. A Ana queria escrever "Fim da lista" uma vez só, depois do for, mas digitou sem a linha vazia:

>>> compras = ["arroz", "feijão"]
>>> for item in compras:
...     print(item)
...     print("Fim da lista")                      « também ficou dentro do for
...
arroz
Fim da lista
feijão
Fim da lista

O "Fim da lista" saiu duas vezes, uma para cada item, porque entrou no bloco que se repete. No modo interativo, termine o bloco com uma linha vazia antes de escrever o que vem depois. (Para apagar o recuo automático de uma linha, use a tecla Backspace.) Para programas com vários blocos, um arquivo é bem mais confortável.

4. Saindo

Há três jeitos de sair do modo interativo e voltar ao $ do terminal:

>>> exit
$

exit ou quit"Sair". No Python 3.13 em diante, sem parênteses
exit() ou quit()Com parênteses: funciona em qualquer versão do Python

Até o Python 3.12 (e, ainda hoje, quando o modo interativo novo está desligado), digitar exit sem parênteses só mostra um recado. A Ana ligou o modo antigo com a variável PYTHON_BASIC_REPL=1 para ver:

$ PYTHON_BASIC_REPL=1 python3 -q

>>> exit()

Se o seu Python for antigo (o Ubuntu 24.04 traz o 3.12), use exit(), com parênteses: funciona em todas as versões.

O que você digitou some ao sair

As variáveis que você criou no modo interativo vivem só enquanto ele está aberto. A Ana saiu e abriu de novo:

$ python3 -q
>>> compras
Traceback (most recent call last):
  File "<python-input-0>", line 1, in <module>
    compras
NameError: name 'compras' is not defined
>>>                                                « aqui a Ana apertou Ctrl+D

A lista de compras da sessão anterior não existe mais: cada vez que você abre o python3, ele começa do zero, como uma calculadora recém-ligada. Por isso, tudo o que você quer guardar vai num arquivo (aula Rodando um Programa (.py)). As linhas que você digitou, porém, ficam no histórico (seção 6), e você pode reaproveitá-las.

6. Atalhos e cores do modo interativo novo 3.14

O Python 3.13 trouxe um modo interativo novo, bem mais confortável, e o 3.14 acrescentou mais coisas. Os atalhos de teclado:

TeclaO que faz
↑ e ↓Anda pelo histórico: traz de volta as linhas que você já digitou (inclusive de sessões anteriores), para repetir ou corrigir. Um bloco de várias linhas volta inteiro, para você editar
← e →Move o cursor dentro da linha, para corrigir sem apagar tudo
TabCompleta nomes: digite pri e aperte Tab, e o Python completa o nome print. No 3.14, completa também nomes de módulos depois de import 3.14
Ctrl+CDesiste da linha que você está digitando (ou interrompe um programa que não para)
Ctrl+LLimpa a tela
F1Abre a ajuda (o mesmo que help)
F2Mostra o histórico só com o que você digitou, sem as respostas e sem os >>>: fácil de copiar para um arquivo
F3"Modo colar": para colar um trecho grande de código sem que a indentação automática atrapalhe. Aperte F3 de novo para sair

Assim fica o Ctrl+C no meio de uma linha que a Ana desistiu de digitar:

>>>
KeyboardInterrupt                                  « "interrupção pelo teclado": a linha foi descartada
>>>

O histórico fica guardado no arquivo ~/.python_history, na sua pasta pessoal, e por isso as setas trazem até linhas de ontem.

As cores

No terminal, o modo interativo do Python 3.14 é colorido: o prompt >>> aparece em destaque, e o código que você digita é colorido enquanto você escreve 3.14. No terminal da Ana, os números saíram em amarelo, os textos entre aspas em verde e os nomes como print e exit em ciano. As mensagens de erro também vêm coloridas (desde o 3.13), com a linha do erro e os ^^^^ destacados. As sessões deste guia aparecem sem essas cores, mas o texto é exatamente o mesmo.

Se as cores atrapalharem (por exemplo, num terminal de fundo claro), dá para desligá-las abrindo o Python assim: PYTHON_COLORS=0 python3. A variável NO_COLOR=1, que vale para muitos programas, também funciona.

7. O editor do guia não é um >>>

As caixas Experimente rodam o código como um arquivo, do começo ao fim, a cada clique em Rodar (como python3 main.py). Por isso, lá:

  • valores soltos não aparecem sozinhos: use print;
  • o _ do último resultado não existe;
  • cada Rodar começa do zero, como um >>> recém-aberto.

Para "conversar" linha por linha com o Python, use o python3 do seu computador. A aula O Editor do Guia mostra tudo o que as caixas fazem.

Quando dá errado

Um erro no >>> não fecha nada 
>>> nome = "Ana"
>>> idade
Traceback (most recent call last):
  File "<python-input-3>", line 1, in <module>
    idade
NameError: name 'idade' is not defined
>>> nome
'Ana'                                              « o que já existia continua lá

O que aconteceu: a Ana pediu idade, que nunca foi criada: "o nome idade não está definido". No modo interativo, o "arquivo" do traceback se chama <python-input-3>: é a entrada de número 3 da sessão (a contagem começa no 0, e a Ana já tinha digitado outras linhas antes dessas). Diferente de um programa em arquivo, o erro não encerra nada: o Python mostra a mensagem e volta ao >>>, com tudo o que você já tinha criado.

Como resolver: crie a variável antes de usar (idade = 30), ou confira se o nome está escrito certo.

Maiúscula no lugar errado: Print 
>>> Print(nome)
Traceback (most recent call last):
  File "<python-input-5>", line 1, in <module>
    Print(nome)
    ^^^^^
NameError: name 'Print' is not defined. Did you mean: 'print'?

O que aconteceu: para o Python, Print e print são nomes diferentes, e só o segundo existe. Ele mesmo sugere: "você quis dizer print?". Como resolver: use as setas (↑) para trazer a linha de volta, corrija o P e aperte Enter.

Comando do terminal dentro do >>> 
$ python3
Python 3.14.4 (main, Aug 20 2026, 10:41:58) [GCC 15.2.0] on linux
Type "help", "copyright", "credits" or "license" for more information.
>>> python3 ola.py
  File "<python-input-0>", line 1
    python3 ola.py
            ^^^
SyntaxError: invalid syntax
>>> ls
Traceback (most recent call last):
  File "<python-input-1>", line 1, in <module>
    ls
NameError: name 'ls' is not defined
>>> exit()

O que aconteceu: python3 ola.py e ls são comandos do terminal, mas quem estava ouvindo era o Python. No primeiro, ele nem entendeu a frase: SyntaxError: invalid syntax, "sintaxe inválida", com os ^^^ embaixo do ola (para o Python, dois nomes lado a lado, separados só por espaço, não formam uma instrução). No segundo, ele entendeu ls como o nome de uma variável que não existe.

Como resolver: saia com exit() e digite o comando no $.

Código Python no terminal

O contrário também acontece: a Ana saiu do Python e, no $, digitou uma linha de Python:

$ print("Olá")
bash: erro de sintaxe próximo ao token inesperado `"Olá"'

O que aconteceu: quem respondeu foi o bash, o programa do terminal, em português e sem Traceback. Os parênteses têm outro significado para ele, e ele não entendeu a linha.

Como resolver: abra o Python primeiro (python3) e digite no >>>, ou grave a linha num arquivo e rode com python3 arquivo.py.

O prompt virou ... e não sai mais

O que aconteceu: o Python está esperando o resto de alguma coisa: um bloco depois de :, um parêntese, colchete ou aspas que não foram fechados. Enquanto aparecer ..., cada Enter só acrescenta uma linha.

Como resolver: feche o que ficou aberto (por exemplo, digite )), ou aperte Enter numa linha vazia para terminar um bloco. Se você se perdeu, Ctrl+C descarta tudo e volta ao >>>.

Missão: a calculadora da feira

Missão: a Ana comprou três coisas na feira: R$ 5,50, R$ 12,00 e R$ 3,25. O programa esqueceu o último preço. Acrescente + 3.25 dentro do print (com ponto, não vírgula) e rode até aparecer o total certo, 20.75. Se tiver o Python instalado, faça a mesma conta no >>>, sem print.

print(5.50 + 12.00)

print(5.50 + 12.00 + 3.25)

Resumo

  • O modo interativo (REPL) é uma conversa com o Python: você digita uma linha, ele responde. Abra com python3 (ou python3 -q, sem a mensagem).
  • $ é o terminal; >>> é o Python. Cada um entende a sua língua.
  • No >>>, o valor de cada linha aparece sozinho (textos com aspas, como 'Ana'); num arquivo, e no editor do guia, só aparece o que vai no print.
  • ... quer dizer "continue": depois de : o recuo vem sozinho, e uma linha vazia termina o bloco.
  • Erros no >>> não fecham nada (o "arquivo" se chama <python-input-N>), mas ao sair tudo o que você criou se perde.
  • Saia com exit, quit, exit() ou Ctrl+D. Peça ajuda com help. Use as setas, o Tab, o F2 e o F3.
  • O Python 3.14 colore o código enquanto você digita; PYTHON_COLORS=0 desliga as cores.
