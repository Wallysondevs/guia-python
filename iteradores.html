Python Iteradores

Desde a aula for, você percorre listas, textos, dicionários e até arquivos com o mesmo for item in coisa:. Nunca precisou dizer "comece do primeiro", "agora o próximo", "pare no último". Quem faz esse trabalho escondido é o iterador (do inglês iterate, "repetir, passar um por um"). Nesta aula você vai abrir o for e ver as peças lá dentro: iter(), next() e o StopIteration. Depois, vai construir o seu próprio iterador.

Você vai aprender
  • A diferença entre iterável (a coisa que dá para percorrer) e iterador (quem percorre).
  • A pedir um iterador com iter() e o próximo item com next().
  • O que é o StopIteration e por que você quase nunca o vê.
  • O que o for faz por dentro, passo a passo.
  • Por que um iterador se gasta e uma lista não.
  • A criar o seu iterador com os métodos __iter__ e __next__.
  • Os erros reais: 'list' object is not an iterator, object is not iterable, iter() returned non-iterator e o laço que nunca acaba.

A ideia: o livro e o marcador de página

Pense num livro de receitas. O livro tem todas as páginas, do começo ao fim, mas não sabe em qual página você parou. Para isso existe o marcador de página: ele lembra onde você está, e cada vez que você pede "a próxima", ele avança uma página. Quando o livro acaba, o marcador avisa: "não tem mais".

  • O livro é o iterável: uma lista, um texto, um dicionário. Ele guarda os itens e sabe criar um marcador novo sempre que alguém pede.
  • O marcador é o iterador: ele só sabe uma coisa, entregar o próximo item, e lembra onde parou.
  • Um livro pode ter vários marcadores ao mesmo tempo (duas pessoas lendo o mesmo livro), e cada um está numa página.

IterávelO livroLista, tupla, texto, dicionário, conjunto, arquivo, range…
iter(coisa)"Me dá um marcador para este livro"Cria um iterador novo, parado antes do primeiro item
next(iterador)"Vira a página"Entrega o próximo item e avança

Lendo o traceback

É o primeiro traceback desta aula, então vamos linha por linha:

  • Traceback (most recent call last): "rastro (a chamada mais recente por último)": o Python vai mostrar o caminho até o erro.
  • File "<python-input-5>", line 1, in <module>: o erro aconteceu na entrada número 5 do modo interativo (ele conta a partir de 0), linha 1, no programa principal.
  • next(it) com ~~~~^^^^ embaixo: o Python 3.14 sublinha a parte culpada; os ^ apontam o (it), a chamada que falhou.
  • StopIteration: o nome da exceção. Repare que ela não traz mensagem nenhuma depois do nome: não há nada para explicar, o iterador simplesmente acabou.
StopIteration não é um defeito

Ao contrário de um NameError ou de um TypeError, o StopIteration é um aviso combinado: é o jeito que todo iterador do Python tem de dizer "acabou". Você só o vê assim, em vermelho, porque chamou next() na mão e ninguém estava esperando o aviso. O for espera por ele, e por isso você nunca o viu nos seus laços.

Missão: na padaria do bairro, o painel chama as senhas uma por vez. O programa já chama a primeira. Acrescente mais duas linhas com next(fila) para chamar a 102 e a 103.

print("Chamando a senha", next(fila))

print("Chamando a senha", next(fila))

Na solução, a última linha mostra Ainda na fila: [104]: o list(fila) pegou só o que sobrou no iterador. O marcador já estava na senha 104.

2. next() com um valor padrão

Se você não quer o StopIteration, passe um segundo argumento ao next(): o valor que ele deve devolver quando acabar. No lugar do erro, vem esse valor, quantas vezes você pedir:

>>> compras = ["pão", "leite"]
>>> it = iter(compras)
>>> type(compras)
<class 'list'>
>>> type(it)
<class 'list_iterator'>
>>> next(it, "acabou")
'pão'
>>> next(it, "acabou")
'leite'
>>> next(it, "acabou")
'acabou'
>>> next(it, "acabou")
'acabou'

Repare também no type(): a lista é uma list, e o iterador dela é outra coisa, um list_iterator ("iterador de lista"). São dois objetos diferentes: o livro e o marcador.

Todo iterável tem o seu iterador

Textos e dicionários funcionam igual. O iterador de um texto entrega uma letra por vez; o de um dicionário entrega as chaves (é por isso que for chave in dicionario: percorre as chaves, como na aula Percorrendo um Dicionário):

>>> letras = iter("café")
>>> next(letras)
'c'
>>> next(letras)
'a'
>>> precos = {"pão": 0.75, "leite": 5.49}
>>> chaves = iter(precos)
>>> next(chaves)
'pão'
>>> next(chaves)
'leite'

3. O for por dentro

Agora dá para entender o for. Os dois laços abaixo fazem exatamente a mesma coisa; o segundo é o que o Python faz, escondido, quando você escreve o primeiro:

compras = ["pão", "leite", "café"]

# 1. O jeito de sempre: o for
for item in compras:
    print("Comprar:", item)

print("---")

# 2. O que o for faz por dentro
it = iter(compras)
while True:
    try:
        item = next(it)
    except StopIteration:
        break
    print("Comprar:", item)

$ python3 por_dentro.py
Comprar: pão
Comprar: leite
Comprar: café
---
Comprar: pão
Comprar: leite
Comprar: café
  1. it = iter(compras): antes da primeira volta, o for pede um iterador à lista.
  2. while True: repete "para sempre" (aula while)…
  3. item = next(it): …pedindo o próximo item e guardando na variável do laço.
  4. except StopIteration: break: quando o iterador avisa que acabou, o try (aula try e except) captura o aviso e o break sai do laço. Sem traceback nenhum.
  5. print("Comprar:", item): o corpo do for, uma vez por item.

É por isso que o mesmo for serve para listas, textos, dicionários, arquivos e range: ele não conhece nenhum deles. Ele só sabe pedir iter() uma vez e next() até vir o StopIteration. Quem souber responder a essas duas perguntas pode ir num for.

4. O iterador se gasta

O marcador de página só anda para a frente. Quando chega ao fim, fica lá. Veja o que acontece ao percorrer o mesmo iterador duas vezes:

senhas = iter([1, 2, 3])

print("Primeira volta:")
for s in senhas:
    print("  senha", s)

print("Segunda volta:")
for s in senhas:
    print("  senha", s)

print("Fim.")

$ python3 gasta.py
Primeira volta:
  senha 1
  senha 2
  senha 3
Segunda volta:
Fim.

A segunda volta não mostrou nada, e também não deu erro. O segundo for pediu iter(senhas), e o iterador de um iterador é ele mesmo, já no fim. O primeiro next() já veio com StopIteration, e o laço acabou sem nenhuma volta.

Agora o mesmo programa com a lista, sem o iter() na primeira linha (senhas = [1, 2, 3]):

$ python3 gasta_lista.py
Primeira volta:
  senha 1
  senha 2
  senha 3
Segunda volta:
  senha 1
  senha 2
  senha 3

Com a lista, cada for pede um iterador novo, que começa do zero: um marcador novo para o mesmo livro. O modo interativo confirma a diferença com o operador is (aula is e in):

>>> it = iter([1, 2, 3])
>>> iter(it) is it
True                       « o iterador de um iterador é ele mesmo
>>> lista = [1, 2, 3]
>>> iter(lista) is lista
False                      « a lista entrega um objeto novo
Quem devolve iteradores (e se gasta)

Várias funções que você já usou devolvem iteradores, e não listas: map() e filter() (aula map() e filter()), zip() e enumerate() (aula enumerate() e zip()), e o arquivo aberto com open(). Todos se gastam na primeira passada.

precos = [4.50, 12.00, 7.25]

print(sum(iter(precos)))
print(max(iter(precos)))
print(list(iter(precos)))
print(sorted(iter(precos)))

com_desconto = map(lambda p: p * 0.9, precos)
print(com_desconto)
print(list(com_desconto))
print(list(com_desconto))

$ python3 consumir.py
23.75
12.0
[4.5, 12.0, 7.25]
[4.5, 7.25, 12.0]
<map object at 0x7fa91a19b640>      « o endereço muda a cada execução
[4.05, 10.8, 6.525]

  • sum(), max(), list() e sorted() aceitam qualquer iterável, inclusive um iterador: eles fazem o próprio laço, com next() até o fim.
  • print(com_desconto) não mostra os preços: mostra o objeto map, que ainda não calculou nada. Os valores só são calculados quando alguém pede, um por um.
  • O primeiro list(com_desconto) pede todos e gasta o iterador. O segundo recebe uma lista vazia, []. (O 6.525 e o 10.8 são os preços com 10% de desconto; para mostrar com duas casas, use as f-strings.)

Se você precisa dos valores mais de uma vez, guarde numa lista logo de cara: com_desconto = list(map(…)).

O arquivo também é um iterador

Um arquivo aberto (aula Lendo Arquivos) entrega uma linha a cada next(). Dá para tirar a primeira linha na mão e deixar o resto para o for, um truque comum para pular o cabeçalho de um arquivo:

pão
leite
café

with open("compras.txt", encoding="utf-8") as arquivo:
    print(type(arquivo))

    print("Primeira linha:", primeira.strip())

5. Criando o seu iterador: __iter__ e __next__

O for só faz duas perguntas: iter() e next(). Por baixo, elas chamam dois métodos especiais do objeto (aula Métodos Especiais): iter(x) chama x.__iter__(), e next(x) chama x.__next__(). Escreva os dois numa classe (aula Classes e Objetos) e os objetos dela vão poder entrar num for.

A Ana quer uma contagem regressiva para a virada do ano:

class ContagemRegressiva:
    def __init__(self, inicio):
        self.atual = inicio

    def __iter__(self):
        return self

    def __next__(self):
        if self.atual <= 0:
            raise StopIteration
        valor = self.atual
        self.atual -= 1
        return valor


for numero in ContagemRegressiva(3):
    print(numero)
print("Já!")

$ python3 contagem.py
3

1
Já!
def __init__(self, inicio):
Guarda em self.atual o número de onde a contagem parte. É a "memória" do marcador: onde ele está agora.
def __iter__(self): return self
A resposta para iter(). Este objeto já é o marcador, então devolve a si mesmo. Todo iterador faz assim.
def __next__(self):
A resposta para next(): entrega o próximo item.
if self.atual <= 0: raise StopIteration
Chegou ao fim? Então lança o aviso combinado com raise (aula raise). Sem esta linha, a contagem nunca acaba (veja em Quando dá errado).
valor = self.atual / self.atual -= 1 / return valor
Guarda o número da vez, anda uma casa e devolve o número guardado. A ordem importa: se você diminuísse antes de guardar, a contagem começaria do 2.

Chamando next() na mão, o StopIteration aparece com o caminho completo. Agora o traceback tem dois trechos: a linha do seu programa que chamou o next() e, embaixo, a linha do __next__ que lançou a exceção:

6. Iterável que pode ser percorrido várias vezes

A ContagemRegressiva é um iterador, e iteradores se gastam: um segundo for no mesmo objeto não mostraria nada. Uma lista não tem esse problema porque ela é um iterável, não um iterador: a cada iter(), ela fabrica um marcador novo. Dá para fazer o mesmo com duas classes, o livro e o marcador:

class Playlist:
    def __init__(self, musicas):
        self.musicas = musicas

    def __iter__(self):
        return PlaylistIterador(self.musicas)


class PlaylistIterador:
    def __init__(self, musicas):
        self.musicas = musicas
        self.posicao = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self.posicao >= len(self.musicas):
            raise StopIteration
        musica = self.musicas[self.posicao]
        self.posicao += 1
        return musica


festa = Playlist(["Asa Branca", "Garota de Ipanema", "Aquarela"])

for musica in festa:
    print("Tocando:", musica)

print("De novo, desde o começo:")
for musica in festa:
    print("Tocando:", musica)

Tocando: Asa Branca

Formas diferentes de fazer um objeto percorrível

Quando os itens já estão guardados numa lista, você não precisa escrever o marcador: o __iter__ pode simplesmente devolver o iterador da própria lista.

class Playlist:
    def __init__(self, musicas):
        self.musicas = musicas

    def __iter__(self):
        return iter(self.musicas)


festa = Playlist(["Asa Branca", "Garota de Ipanema", "Aquarela"])
print(list(festa))
print(list(festa))
print("Aquarela" in festa)

$ python3 playlist_curta.py
['Asa Branca', 'Garota de Ipanema', 'Aquarela']
['Asa Branca', 'Garota de Ipanema', 'Aquarela']
True

Funciona com list(), com for e até com in: o in também percorre o iterável, item por item, até achar. A terceira forma, a mais usada no dia a dia, é a função geradora, com yield, da próxima aula, Geradores: ela escreve o __iter__ e o __next__ para você.

FormaQuando usar
__iter__ devolvendo iter(self.lista)Os itens já estão numa lista (ou tupla, dicionário) dentro do objeto. A mais curta
Classe com __iter__ e __next__Para entender como tudo funciona, ou quando o marcador precisa de uma lógica própria (uma contagem, uma leitura aos pedaços)
Duas classes: iterável + iteradorQuando o objeto precisa ser percorrido várias vezes, ou por dois laços ao mesmo tempo
Função geradora com yieldQuase sempre, na prática: faz o mesmo que a classe com bem menos linhas (aula Geradores)

Quando dá errado

next() direto na lista 
compras = ["pão", "leite", "café"]
print(next(compras))

$ python3 next_lista.py
Traceback (most recent call last):
  File "/home/ana/next_lista.py", line 2, in <module>
    print(next(compras))
          ~~~~^^^^^^^^^
TypeError: 'list' object is not an iterator

TypeError: 'list' object is not an iterator: "um objeto lista não é um iterador". A lista é o livro, não o marcador: ela não sabe qual é o "próximo". O ~~~~^^^^^^^^^ aponta a chamada next(compras) na linha 2. Como consertar: peça o iterador antes, it = iter(compras), e chame next(it).

Classe sem __iter__ no for

A ContagemRegressiva com o __next__ certinho, mas sem o __iter__:

$ python3 sem_iter.py
Traceback (most recent call last):
  File "/home/ana/sem_iter.py", line 13, in <module>
    for numero in ContagemRegressiva(3):
                  ~~~~~~~~~~~~~~~~~~^^^
TypeError: 'ContagemRegressiva' object is not iterable

"O objeto ContagemRegressiva não é iterável". Antes da primeira volta, o for chama iter(), e o objeto não sabe responder: falta o __iter__. Ter o __next__ não basta. Como consertar: acrescente def __iter__(self): return self.

Classe sem __next__

O contrário: o __iter__ devolve self, mas a classe não tem __next__. É o código inicial da missão final:

$ python3 pares_ini.py
Traceback (most recent call last):
  File "/home/ana/pares_ini.py", line 12, in <module>
    print(list(Pares(10)))
          ~~~~^^^^^^^^^^^
TypeError: iter() returned non-iterator of type 'Pares'

"iter() devolveu um não-iterador, do tipo Pares". O __iter__ prometeu um marcador e entregou um objeto que não sabe fazer next(). Como consertar: escreva o __next__.

Não há erro nenhum no código, do ponto de vista do Python: o __next__ sempre tem um número para entregar, então o for nunca recebe o aviso de fim. A contagem passa do zero e segue pelos negativos até alguém apertar Ctrl+C. O terminal mostra o ^C na hora em que a tecla é apertada, por isso ele aparece colado no último número, que o Python ainda terminou de escrever. O Ctrl+C interrompe o programa com KeyboardInterrupt ("interrupção pelo teclado"). A linha que aparece no traceback é a que estava rodando no instante do Ctrl+C, e pode ser outra no seu terminal. Como consertar: todo __next__ precisa de um caminho que termine em raise StopIteration. (Por isso este exemplo fica só no terminal: não rode um laço sem fim no editor do guia.)

O in gastou o iterador (sem erro nenhum)

Sumiram o pão e o leite! Para responder ao in, o Python chamou next() até achar o "leite" e parou ali. O for continuou de onde o marcador ficou. É um erro de lógica: o programa roda, mas a resposta está errada. Como consertar: use a lista (sem o iter()), ou guarde uma lista com list(…) se o que você recebeu é um iterador.

        return self

    def __next__(self):
        if self.atual > self.limite:
            raise StopIteration
        valor = self.atual
        self.atual += 2
        return valor


print(list(Pares(10)))

Com o __next__ no lugar, sai [0, 2, 4, 6, 8, 10]. Experimente trocar o list(Pares(10)) por um for e por sum(Pares(10)): o mesmo objeto serve para tudo que percorre.

Resumo

  • Iterável é o que dá para percorrer (o livro); iterador é quem percorre e lembra onde parou (o marcador).
  • iter(x) pede um iterador; next(it) entrega o próximo item; no fim, vem o StopIteration, ou o valor padrão de next(it, padrao).
  • O for é um iter() seguido de next() até o StopIteration, que ele captura em silêncio.
  • Um iterador se gasta: só anda para a frente. Listas não se gastam porque cada for pede um iterador novo. map, filter, zip, enumerate e arquivos são iteradores.
  • Para criar o seu: __iter__ devolve self; __next__ entrega o próximo ou lança StopIteration. Sem o raise, o laço nunca acaba.
